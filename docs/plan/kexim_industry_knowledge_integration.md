# 수출입은행 산업보고서의 위키·구조화 지식 통합 설계

작성일: 2026-10-05 (Asia/Seoul). 상태: **후속 설계, 미구현**.

관련: [시장자료 강화 계획](kexim_market_data_integration.md), [현재 구현·검증 기록](kexim_market_data_mvp_status.md).

## 1. 목표와 현재 확인 범위

수출입은행 산업보고서에서 산업 구조·수익 동인·시장규모·CAGR을 추출해 **위키 → 출처가 있는 관측 데이터 → 기업별 가정 → 계산 모델**로 연결한다. 지식의 내재화는 버전이 있는 문서와 데이터 저장소를 검색해 재사용하는 방식으로 시작한다. 변하는 시장 전망을 모델의 학습 가중치에만 저장하면 출처·발행시점·수치 수정 이력을 추적하기 어렵다.

| 구분 | 2026-10-05 확인 결과 |
|---|---|
| 공식 제공 경로 | [공공데이터포털 한국수출입은행 ICT산업동향](https://www.data.go.kr/data/15045162/fileData.do)은 해외경제연구소의 ICT 산업보고서를 PDF로 제공하는 기관 다운로드 URL을 안내한다. 수치 조회 API로 등록된 자료는 아니다. |

공개 범위는 저장소의 기존 정책을 따른다. 원문·발췌 코퍼스와 보고서별 수치 저장소는 로컬 비공개 영역에 보관하고, 공개 레포에는 귀납한 방법론·스키마·검증 코드만 추가한다. 권리 확인과 공개 범위 변경은 별도 작업으로 다룬다.

## 3. 저장할 지식의 세 가지 형태

| 형태 | 내용 | 사용처 |
|---|---|---|
| 산업 위키 | 밸류체인, 제품 분류, 수익 동인, 공급·수요 제약, 규제, 리스크, 가설이 깨지는 조건 | 산업 이해, 질문 응답, 매출·원가 드라이버 선택 |
| 관측 데이터 | 시장규모·CAGR·점유율·생산능력 등과 정의·기간·지역·단위·출처 페이지 | 숫자 검색, 재계산, 같은 정의의 전망 비교 |
| 기업 적용 기록 | 해당 제품/지역의 노출, 점유율·가격·능력 제약, 채택 성장률, 사유·작성자·시각 | 가정 원장, 시나리오, 모델 입력의 근거 추적 |

산업 위키의 설명 문장에는 근거 ID를 붙인다. 새로운 보고서가 들어오면 기존 내용을 삭제하지 않고 변경 이유·새 근거·이전 버전을 남긴다. 발표된 예측이 나중에 실제와 달라져도 과거 평가에서 사용한 자료를 복원할 수 있어야 한다.

아래는 구현 예정 필드다. 필수 의미를 읽을 수 없으면 `null` 또는 `unknown`으로 남기고 모델 채택을 차단한다.

| `IndustryClaim` | `claim_id`, `industry_id`, `claim_type`, `statement`, `supports_metric_ids[]`, `supports_report_pages[]`, `assumptions`, `counter_conditions`, `valid_from`, `superseded_by`, `review_status` |

`basis`는 금액/수량/출하량/설치량 등을 구분한다. `price_basis`는 명목/실질/고정가격 여부다. `reported_value`는 원문 표현을 보존하고, 정규화된 비율은 소수 단위로 별도 저장한다. 10%의 정규화 값은 0.10이며 퍼센트포인트 차이는 이와 다른 필드다.

보고서의 발행기관과 실제 시장규모를 추정한 조사기관을 둘 다 남긴다. 재인용 자료를 원출처 확인 없이 직접 읽은 데이터로 표시하지 않는다. 페이지 번호는 PDF 페이지와 인쇄된 페이지를 분리한다. 관측 ID에는 보고서 해시와 표 위치를 포함해 개정본을 새 관측으로 저장한다.

## 5. CAGR 검증 규칙

```text
n = 종료 연도 - 시작 연도
CAGR = (종료 값 / 시작 값)^(1 / n) - 1
```

1. 시작·종료 값이 양수이고 동일한 정의·지역·단위·가격 기준인지 확인한다. 연간 간격이 명확한 기간만 위 식을 사용하며, `n`을 관측치 개수로 계산하지 않는다.
2. 보고서 기재 CAGR과 직접 재계산한 CAGR을 모두 보존한다. 반올림 오차 기준은 원문 표시 자릿수와 입력 값의 반올림 정도를 근거로 설정하고 검토 기록에 남긴다.
3. 끝점 값이 없으면 `reported_only`로 저장한다. 재계산 성공으로 표시하지 않는다. 끝점이나 정의가 다르면 `definition_mismatch`, 값이 맞지 않으면 `needs_review`로 둔다.
4. 과거 실적 CAGR과 전망 CAGR을 구분한다. 전망 기간이 달라지거나 제품 범위가 다르면 직접 평균·순위 비교를 만들지 않는다.
5. 금액 기준 시장 성장률을 수량 성장률로 복사하지 않는다. 영구성장률에 유한 기간의 산업 CAGR을 그대로 적용하지 않는다.

검증은 LLM의 수치 계산 결과를 받아들이는 방식이 아니라 순수 계산 함수와 입력 대사로 수행한다. OCR 수치·표의 헤더·각주는 원문 페이지에서 사람이 확인하고, 누락된 숫자를 생성하지 않는다.

## 6. 평가기준일과 검색

자료가 조회 시점에 존재한다는 사실과 평가기준일에 이용 가능했다는 사실은 별개다. 기본 검색은 `published_at <= valuation_date`로 제한하고, 발행일 미상 자료는 과거 평가 근거 후보에서 제외한다. 과거 기준일 이후에 수집한 자료는 그 당시 공개되어 있었다는 추가 근거를 요구한다. 수집시각은 발행시각을 대신하지 않는다.

검색 흐름은 다음과 같이 설계한다.

```text
기업·제품군·지역·평가기준일
 → 산업/제품 분류 매칭
 → 발행일·검토 상태·권리 상태 필터
 → 산업 위키의 관련 섹션 + 관측 데이터 검색
 → 인접 밸류체인·매출동인 연결
 → 근거 페이지·숫자 정의·제약이 붙은 후보 응답
```

LLM은 구조화 저장소에 존재하는 관측 ID와 값을 인용한다. 수치 후보가 없으면 결측으로 답한다. 동일 정의의 전망이 충돌하면 출처별 값·발행일·기간을 나란히 보여주고, 선택 이유를 기록한다. 새로운 전망을 최신이라는 이유만으로 과거 관측 위에 덮어쓰지 않는다.

## 7. 기업 매출과 모델에 연결하기

산업 CAGR은 기업 성장률을 검토하는 출발 자료다. 제품군·지역 노출을 공시나 확인된 기업 자료로 매핑한 뒤 점유율, 가격, 생산능력, 수주·납기 제약을 반영한다.

```text
금액 기준 시장규모 × 해당 시장의 기업 점유율 → 해당 제품군 매출
수량 기준 수요 × 점유율 × 기업 ASP → 해당 제품군 매출
공급 제약이 있는 사업 → 수량·가동률·생산능력 제약을 추가
```

시장규모가 이미 금액 기준이면 가격 성장률을 다시 곱해 이중 계산하지 않는다. 제품군별 매출을 합산하고 기존 매출·생산능력과 대사한다. 성장률을 채택할 때는 후보 근거 → 변환 논리 → 선택 값 → 모델의 대상 셀을 보여주고 평가인이 승인한다. DCF의 가치 민감도와 재계산 결과는 별도로 확인한다.

## 8. 구현 순서와 완료 조건

| 단계 | 산출물 | 완료 조건 |
|---|---|---|
| IK01 소규모 자료 등록 | 한 산업의 보고서 3~5편 목록·파일 해시·권리/발행일 메타데이터 | 본문 접근과 페이지 확인. 미확인 항목 표시, 원문 비공개 저장 |
| IK02 구조화·검증 | 시장규모/CAGR 등 10~20개 후보와 검토 원장 | 각 후보의 정의·단위·기간·페이지 대사. 재계산 가능한 CAGR 검증 |
| IK03 산업 위키 | 밸류체인·동인·리스크 문서와 근거 ID | 문장마다 근거 또는 평가인의 해석 표시. 공개 방법론과 비공개 출처 데이터 분리 |
| IK04 검색 연결 | 산업/제품/지역/기준일 필터와 출처 응답 | 미래 발행 자료 제외, 정의가 다른 성장률 분리, 숫자 결측을 생성하지 않는 회귀 사례 |
| IK05 기업 적용 | 한 기업의 제품군별 가정 원장·Excel 연결 | 노출 근거, 가격 이중 계산 방지, 명시적 채택·모델 재계산·추적 가능성 확인 |

3~5편·10~20개는 파일럿의 목표 범위이며 실제 확보된 수치가 아니다. 첫 산업은 보고서 본문 접근·수치 정의 확인 후 고른다. ICT는 공식 제공 목록을 확인했지만 아직 후보 산업이다.

후속 코드의 책임은 수집/추출, 구조화 저장, 순수 CAGR 계산·검증, 검색, 기업 적용을 분리한다. 기존 `MarketSnapshot`은 일별 환율·금리 계약이므로 산업 전망을 같은 객체에 억지로 넣지 않는다. 근거 ID와 불변 저장·명시적 채택이라는 원칙만 공유한다.

파일럿을 마친 뒤 산업 수를 늘린다. 로컬 지식의 클라우드 배포, 정기 수집, 알림, 학습 데이터 제작은 추가 범위로 남긴다.
