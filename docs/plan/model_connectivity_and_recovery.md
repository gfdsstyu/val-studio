## 1. 문제 — 두 트랙이 같은 벽에 부딪힌다

| | 감사인 트랙 | 평가인 트랙 |
|---|---|---|
| 받는 것 | 평가인이 준 **값 붙여넣기 워크북**(수식 없음) | 자기가 키운 모델(수식 있음) |
| 질문 | "이 숫자가 **어디서** 왔나" | "내 모델이 **어디서** 끊겼나" |
| 지금 가능 | 독립 재계산(입력을 손으로 재입력) | 정적 감사(수식 패턴·하드코딩) |
| 지금 불가능 | 경영진 모델 자체를 테스트 | 연결 끊김 탐지 |

**공통 기반**: 셀 참조를 엣지로 하는 **의존성 그래프**. 평가인은 그래프를 *읽고*,
감사인은 그래프가 *없어서* 역추론한다 — 같은 자료구조의 앞뒷면.

### 왜 지금 도구로 안 되는가

- 값-only 워크북에서는 `model_audit`(수식 패턴·하드코딩)이 **완전 무력**하다. 분석할
  수식이 없다.
- 수식이 있어도 정적 감사는 "이웃과 다른 셀"만 본다. **"이 가정이 결과에 도달하는가"**
  는 보지 않는다.

> ⭐ **핵심**: "WACC를 고쳤는데 주당가치가 안 변한다"는 사람이 못 알아챈다. 숫자는 멀쩡히
> 나오고 대차도 맞고 정적 감사도 통과한다. **오직 그래프만** "이 가정은 결과에 도달하지
> 못한다"고 말할 수 있다.

## 2. "끊김"의 유형 — 전부 비올에서 실제로 겪은 것

| 유형 | 비올 실사례 | 그래프에서의 모습 |
|---|---|---|
| **시트 간 단절** | WACC 탭이 빈 템플릿인데 `DCF!H37`은 11.3% 상수 → WACC 시트를 고쳐도 결과 불변 | WACC 노드 → per_share **경로 없음** |
| **하드코딩 잎** | `H37`(WACC)·`H38`(g) 상수 | 잎 노드인데 가정 성격 → 승격 후보 |
| **깨진 외부 링크** | 리포트가 Downloads 경로의 옛 모델 참조 | 외부 파일 엣지 |
| **고아 계산** | 리포트 내장 모델탭이 13,114원을 표시하는데 아무도 안 씀 | out-degree 0 계산 노드 |
| **값으로 죽은 수식** | 값 붙여넣기로 상류 단절 | 계산 자리의 상수 노드 |
| **미검증 구간** | CHECK 행 없는 시트(WC·FA·EBIT)에서 결함 9건, 있는 시트(H_FS)는 0건 | 목표 도달 경로에 검증 노드 부재 |

## 3. 설계

### 3-1. 공통 엔진 — `backend/excel/dependency_graph.py`

```
build_graph(workbook) -> DependencyGraph
  노드 = 셀(sheet!ref).  종류: formula | constant | empty | error | external
  엣지 = 참조(선행 → 후행)

trace_precedents(target, depth=None)   역방향 — "이 셀은 무엇에 의존하는가"
trace_dependents(cell)                 순방향 — "이 셀을 바꾸면 어디가 바뀌는가"
find_breaks(graph, targets, hints)     끊김 진단(§3-2)
cycles(graph)                          순환 참조(3표 이자 순환은 정상 — 화이트리스트)
formula_ratio(graph)                   수식 비율 → 값-only 판정(감사인 트랙 분기)
```

**설계 결정**

| 쟁점 | 결정 | 이유 |
|---|---|---|
| 범위 참조(`SUM(A1:A10)`) | **범위 노드**로 두고 멤버는 lazy 확장 | 즉시 확장하면 대형 워크북에서 노드가 폭발한다. 도달성 판정에는 범위 노드로 충분 |
| 동적 참조(`INDIRECT`·`OFFSET`) | **추적 불가로 표시**(unknown 엣지) | 정적 분석의 원리적 한계. 조용히 무시하면 "도달 안 함"이라는 **거짓 결론**이 난다 |
| 이름 정의(named range) | 워크북 정의를 해석해 셀로 치환 | 미해석 시 대량 오탐 |
| 타 워크북 참조 | 외부 노드(값만 보유) | 열 수 없는 파일이 대부분 |
| 순환 | 검출하되 **정상 순환 화이트리스트**(3표 이자) | R14 Circuit Switch 규약과 정합 |

### 3-2. P1 — 평가인: 모델 연결성 진단

**진입**: `5. 산출물 › 모델 연결성`(신규 시트) 또는 Task Pane의 "현재 워크북".

**절차**
1. 목표셀 지정 — 기본은 주당가치. 표준 레이아웃이면 `RESULT["per_share"]`, 아니면 사용자가 지정(라벨 검색 보조).
2. 역방향 도달 집합 계산 → **결과에 실제로 영향을 주는 셀**.
3. 진단 4종 산출:

| 진단 | 판정 | 산출 |
|---|---|---|
| **끊긴 가정** | 계산되지만 목표에 도달 못 하는 상류 블록 | 시트·범위 + "왜 안 닿는가"(중간 상수 노드 지목) |
| **하드코딩 잎** | 도달 경로상의 상수 노드 | 승격 후보 + **대체 수식 제안** |
| **고아 계산** | out-degree 0 인 수식 노드 | 시트·범위(삭제 후보 아님 — 표시만) |
| **오류·외부** | `#REF!` 등 오류 셀, 외부 파일 엣지 | 목록 |

4. **수정 워크플로우**: 지목 → 대체 수식 제안 → 적용은 사용자(또는 Range 쓰기) →
   **재진단 + 주당가치 불변 tie-out**.

> ⚠️ 4단계의 tie-out 이 이 워크플로우의 안전장치다. 연결을 이었는데 **값이 바뀌면 원래
> 틀렸다는 뜻**이므로, 변화량을 명시하고 별도 판단을 받는다(promote.py 가 이미 쓰는 규율).

### 3-3. P2 — 감사인: 값-only 모델 복원

**진입**: 워크북의 수식 비율이 임계 미만이면 자동으로 이 모드를 안내.

**복원 가능한 것**(값만으로도 산술적으로 도출)

| 항목 | 방법 |
|---|---|
| 구조 관계 | 행 간 산술 항등 탐색 — `매출 − 원가 = 매출총이익`, `Σ부문 = 합계` 조합 |
| 유의적 가정 | 비율 시계열 역산 — 성장률·원가율·판관비율·CAPEX/매출·회전기일 |
| 할인율 | 할인계수 행이 있으면 `PV/FCFF` 에서 **WACC 역산**(연도별 일관성으로 mid-year 여부까지 판별) |
| 영구성장률 | `TV = FCFF_T/(WACC−g)` 에서 **g 역산** |
| 산술 정확성 | `EV = ΣPV + PV(TV)`, `지분 = EV + 비영업 − 순차입 − NCI` 항등식 검산 |
| 구조버그 | 복원된 스파인으로 `diagnose_dcf_gap` 재실행 |

**복원 불가능한 것 — 반드시 함께 표기**

- 가정이 **어떤 외부 데이터에서** 왔는지(원천 연결은 문서·질의로만)
- 가정의 **근거·판단 과정**
- 숨은 오버라이드와 정상 계산의 구분

→ 산출물은 "복원된 모델"이 아니라 **"복원 후보 + 미해결 목록"**. 미해결 항목이 곧
감사인의 **질의사항(inquiry)** 이 된다. 이 경계를 흐리면 도구가 감사 증거인 척하게 된다.

### 3-4. P3 — 가정 ↔ 근거 원장 (감사인)

복원·추출된 가정마다 감사인이 근거를 붙이는 원장. 형식은 기존 자산 재사용
(`scripts/assumption_check.py` 의 YAML 원장, `_VS_STATE` 가정 대장).

```
가정: 2026 매출성장률 12%          ← 복원값(도구)
근거: 산업 리포트 p.14 CAGR 9%      ← 감사인이 연결
판정: +3%p 초과 → 질의 필요         ← 게이트(checks 산업 대조와 연결)
```

ISA 540 의 "가정의 합리성 평가"를 코드화한 형태. 기존 `check_metric_vs_industry`·
`check_consensus_anchor` 를 그대로 소비한다.

## 6. 한계·비목표 (정직 표기)

- **정적 분석의 한계**: `INDIRECT`·`OFFSET`·VBA 는 추적 불가. 조용히 넘기지 않고
  unknown 으로 **표면화**한다("도달 안 함"이라는 거짓 결론 방지).
- **끊김 ≠ 오류**: 의도적으로 상수를 둘 수 있다(외부 확정값 등). 도구는 지목만 하고
  판단은 사람이 한다.
- **복원 ≠ 감사 증거**: P2 산출물은 후보다. 원천·근거 확인은 도구 밖의 절차다.
- **자동 수정 금지**: 수식 교체는 제안까지. 적용은 사용자 확인 후, 그리고 항상 tie-out.
