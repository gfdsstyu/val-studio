## 0. 전제가 되는 구조적 사실 2개

1. **애드인끼리는 직접 통신할 수 없다.** 각자 격리된 iframe, 크로스 애드인 API 없음.
   유일한 공유 매체 = **워크북 자체**(셀 + `_VS_STATE` 숨김 시트) + 클립보드 + 사람.
   → 기존 `_VS_STATE` 증적 설계(Claude 기록 → `excel/vs_state.py` 파싱)는 부가 기능이
   아니라 **유일하게 가능한 애드인 간 프로토콜**이다. 새로 발명할 것이 없다.
2. **역할 분담은 강제로 갈린다.**
   - Val-Studio Task Pane = **데이터 커넥터(BYOK)** + **결정론 계산·게이트(정본)**.
     Claude for Excel 은 BYOK 키를 들 수 없고 우리 API 를 못 부른다 → DART/ECOS 는
     반드시 Val-Studio 경유.
   - Claude for Excel = **워크북의 손**(셀 기입·수식·서사) + 판단 보조. 단 스크립트 실행
     불가 → 스킬은 "결정론 미검증" 지시문 모드(SKILL.md 이중 환경 규약). 검증은
     Val-Studio 로 돌아와야 닫힌다.
   - 사람 = 판단 + (당분간) 셔틀.

## 2. 표준 레이아웃 뉘앙스 (중요)

임의 템플릿은 표준 레이아웃이 아니므로 Val-Studio 4방향 중 **정적 감사만** 가능
(import·diff·중심셀 검산 불가). 해소 전략 = **표준 스파인 병설**: Claude for Excel 에게
템플릿 옆에 표준 `DCF` 시트를 병설시키면(스킬 W0 모드 C + promote 패턴) 임의 템플릿도
왕복 가능계로 들어온다. 원본 ↔ 표준 시트 대사는 CHECK 행으로.

또 하나의 프레임: "내 템플릿에서 시작"은 본질적으로 **평가인 UI 를 쓰는 감사인 트랙**이다
— 과거의 내 모델을 독립 재계산으로 대조하는 구조. 템플릿 신뢰가 아니라 검증이 기본자세.

## 7. 배치 비교 — Task Pane vs 브라우저 탭(로컬/Cloud Run) (2026-08-01 추가)

Val-Studio 를 어디에 띄우느냐로 3가지 배치가 있고, 마찰 지점이 다르다.

| 배치 | 형태 |
|---|---|
| **A** | 엑셀(웹/데스크톱) 안 Task Pane + Claude for Excel |
| **B** | 브라우저 탭에 Val-Studio(Cloud Run 호스팅) + 엑셀 별창 + Claude for Excel |
| **B'** | 로컬 uvicorn(localhost) 탭 + 데스크톱 엑셀 + Claude for Excel |

### 7-1. 핵심 통찰: 모든 마찰의 뿌리는 "정본 분기(fork)"

**워크북과 서버 프로젝트, 정본이 2개가 되려는 순간 전 배치가 무너진다.**
- **A 는 구조적으로 분기가 안 생긴다**: getFileAsync 는 *열려 있는 그 워크북*을 단방향으로
  읽는다 → 워크북=정본 1개, 패널=검증기·데이터 공급기. 사본이 생길 계기가 없다.
- **B 는 매 검증 루프가 사본을 만든다**: 웹 엑셀→다운로드 = 사본(다운로드 폴더에
  (1)(2)(3) 누적), 반영 후 export = 또 다른 새 파일 → OneDrive 재업로드하면 **Claude for
  Excel 이 보던 워크북과 별개 파일로 분기**. 어느 파일이 정본인지 사람이 관리해야 한다.
  ReexportButton 이 타임스탬프 파일명을 붙이는 것 자체가 이 증상의 완화책이다.

### 7-2. 단계별 마찰 비교 (내 템플릿 시나리오 §1 기준)

| 단계 | A(Task Pane) | B(웹 탭 + 웹 엑셀) | B'(로컬 + 데스크톱 엑셀) |
|---|---|---|---|
| 화면 | 350px 협폭(§5 로 완화) — 셀과 나란히 | **풀스크린 1040px** — 전 시트 UI 정상, 대신 알트탭/시선 3분할 | B 와 동일 + 모니터 2개면 최적 |
| DART→셀 (다리 1) | 협폭 표에서 복붙 | 넓은 표에서 복붙 — **오히려 A 보다 편함** | 동일 |
| 검증 루프 (다리 2) | ✅ **getFileAsync 원클릭** (v1.2) | 🔴 다운로드(사본)→업로드 매 루프 + 사본 누적 | 🔶 저장→파일선택 업로드(로컬 파일이라 다운로드는 없음, 엑셀 열림 중 잠금·stale 주의) |
| 반영(웹→워크북) | 🔶 새 export 열기(분기) — 근본 해소는 Range 쓰기(다리 3) | 🔴 export→OneDrive 업로드→**정본 분기** | 🔶 export→열기(로컬이라 한 단계 적음) |
| 프로젝트 상태 | Cloud Run: **GCS 미설정 시 휘발** — diff 기준선 소실 위험 | 동일 | ✅ var/projects 파일 영속 |
| BYOK 키 | Task Pane iframe = 3rd-party 컨텍스트 → **storage partitioning 으로 웹 탭과 localStorage 분리** 가능(키 재입력) — 실측 필요 | 탭 localStorage 정상 | 동일(오리진 localhost 별도) |
| Claude for Excel 과의 관계 | 워크북 매개(§0-1) — 배치 불변 | 동일하나 검증 셔틀이 수동이라 Claude 수정→검증 사이클이 무거움 | 동일 |

### 7-3. 배치별 함정 요약

- **공통(A·B)**: Cloud Run 프로젝트 저장 비영속(GCS 버킷 미설정) — 왕복 diff 의 기준선
  (저장본)이 인스턴스 재시작에 날아간다. **GCS 설정이 이제 '미해결 3건' 중 실사용
  전제조건으로 승격**된다.
- **로컬(B') ↔ 호스팅(A·B) 상태 분단**: var/projects 는 서버별 — 로컬에서 만든 프로젝트가
  호스팅에 없다. **한 프로젝트는 한 서버에서만** 규율 필요(혼용하면 기준선이 어긋난 diff).
- **B 전용**: 정본 분기(§7-1) + 사본 파일 누적. 웹 엑셀 다운로드는 autosave 시점 스냅샷.
- **A 전용**: 협폭 UI(가정 스튜디오·리뷰 패널 같은 넓은 시트는 불편), Task Pane 2개 동시
  표시 여부 미실측(§4-④), Task Pane WebView/iframe 저장소 격리로 BYOK 재입력.
- **B' 전용**: Claude for Excel 은 클라우드 서비스라 로컬 서버(localhost)의 존재를 모른다
  — 상관없음(통신은 어차피 워크북 매개)이지만, 웹 엑셀에서 localhost Task Pane 은 HTTPS
  요건 때문에 dev 인증서 필요.

### 7-4. 권장 운용 모델 — "패널=루프, 탭=스튜디오"

배치는 택일이 아니라 **역할 분담**이 정답이다. 같은 Cloud Run 오리진을 쓰면 Task Pane 과
브라우저 탭이 **같은 프로젝트 목록을 공유**하므로:

1. **검증 루프·데이터 수급 = Task Pane(A)** — getFileAsync 원클릭, 셀 옆에서.
2. **넓은 작업(가정 스튜디오·L3 리뷰·상대가치) = 브라우저 탭(B)** — 같은 프로젝트를
   풀스크린으로. 탭에서 저장하면 패널의 diff 기준선도 같이 갱신된다.
3. **워크북이 유일 정본**, 서버 프로젝트는 "검증 캐시+기준선"으로만 취급(현 설계 그대로).
4. 반영 방향(서버→워크북)은 Range 쓰기(다리 3)가 생기기 전까지 "값 복붙"이 분기 없는
   차선 — 새 export 파일 열기는 정본 교체 의식을 갖고 할 것.
5. 전제 정비: GCS 버킷 설정(기준선 영속) + BYOK 파티셔닝 실측 + Task Pane 2개 동시 실측.

셀 작업=Claude for Excel, 루프의 매듭은 항상 패널의 '현재 워크북 검증'.**

준비(프로젝트당 1회): 엑셀에서 템플릿+Claude 패널 → 옆 탭에 Val-Studio(Cloud Run)
프로젝트 생성(같은 오리진이라 패널과 프로젝트 공유) → BYOK 키 탭·패널 각 1회.

| # | 단계 | 어디서 | 무엇을 |
|---|---|---|---|
| 1 | 자료 수급 | 웹 탭 | DART 재무·주식수(D7)·타법인출자, PDF 업로드→추출 |
| 2 | 자료→셀 | 사람+Claude | 표 복사 → Claude 에게 "`rFS` 시트에 붙여"(r-시트 격리 규약) |
| 3 | 표준 스파인 병설 | Claude | 템플릿 옆에 표준 `DCF` 시트(스킬 W0 모드 C) → 임의 템플릿을 왕복 가능계로 |
| 4 | 가정·추정 구축 | 웹 탭+Claude | 매핑→거시(PGR 앵커)→매출 트리→원가→FA/WC→peer/WACC, 탭에서 저장하며 진행 |
| 5 | DCF 계산·조립 | 웹 탭 | `/api/dcf/assemble` — 게이트 통과분만 채택, 저장 = **diff 기준선** |
| 6 | **검증 루프 ★** | 패널 | Claude 수정 때마다 "현재 워크북으로 비교/감사" 원클릭 → 4버킷·findings·증적 → 입력만 부분 반영 → 반복(다운로드 0) |
| 7 | L3 리뷰·시나리오·상대가치 | 웹 탭 | 실적 다개년→분석적 리뷰, 결함 Δ원장, 민감도 |
| 8 | 산출 | 웹 탭+Claude | 의견서 초안+린트 → 최종 export(수식 live) — 이때만 새 파일 |

남은 수동 지점: 2번 복붙(→ 백로그 ①TSV·③Range 쓰기로 소멸 예정), 서버→워크북 반영은
"값 복붙"이 분기 없는 원칙. 전제 정비 1순위 = **GCS 버킷**(기준선 영속).

## 10. 현업 관점 — 실무 사용 실태와 제품 형태 (2026-08-01 추가)

### 10-1. Big4 Deal/밸류 실무의 실태 (도구 형태를 결정하는 제약)

- **엑셀이 절대 정본** — 모델 작성·리뷰(EQCR)·아카이브 전부 엑셀. "웹으로 옮겨라"는
  도구는 시니어 단계에서 채택이 죽는다.
- **데이터는 셀 함수로 들어온다** — CIQ·Bloomberg·FnGuide·KISVALUE 전부 엑셀 애드인의
  커스텀 함수(`=CIQ()`·`=BDP()`) + F9 리프레시가 표준. 패널 조회→복붙조차 현업 기준
  한 단계 무겁다.
- **리뷰가 진짜 병목** — 셀 추적·tie-out·하드코딩 사냥이 사람 손. 모델 리뷰 전문
  도구(Operis OAK·PerfectXL 류)의 국내 보급은 제한적 → **본 레포의 정적 감사·게이트가
  정확히 이 빈자리**.
- **보안이 형태를 결정** — 클라이언트 데이터의 외부 SaaS 반출은 원칙 금지. 승인된
  도구·키 미보관 설계만 생존(BYOK·서버 시크릿 0 설계가 우연히 정합).
- **조서화 요구(ISQM)** — "도구가 뭘 검사했고 왜 통과시켰나"의 증적이 조서에 남아야
  한다 → findings 에 근거 문서·기준 계보를 다는 설계 방향이 맞다.

### 10-2. 법인이 만든다면 — 형태 4개 승률

| 형태 | 모습 | 채택 승률 | 비고 |
|---|---|---|---|
| ① 엑셀 함수 애드인 | `=VS.DART(...)`·`=VS.WACC(...)` + 리본 검증 버튼 | **최고** | CIQ 가 증명한 모델. 다리 1·3 이 함수로 소멸. Office.js custom functions |
| ② 모델 검증 게이트웨이 | 워크북 제출→게이트 검사→감사 리포트+승인 워크플로우("모델의 CI/CD") | 높음 | **구매자=리뷰어(매니저)**. 생산성 아닌 품질관리 도구 — "안 쓰면 리스크"로 팔림. 본 레포 audit/diff 가 코어 |
| ③ 웹 스튜디오 | 현 val-studio 전체 UI | 낮음(현업)/높음(교육·주니어 방법론 훈련) | 시니어는 엑셀을 안 떠남 |
| ④ 에이전트+스킬 | Claude for Excel + 결정론 스킬 | 상승 중 | 법인 보안 승인이 관문. vendored 스킬이 이 트랙 |

법인 내부 정답 = **①+② 조합**: 작성자는 함수로 셀에서 쓰고, 제출 시점에 게이트웨이가
결정론 검사→증적 조서화. 웹 UI 는 관리 대시보드로 축소.

### 10-3. 본 프로젝트의 대안 경로 (백엔드 변경 0)

- **A. VBA/Office Scripts 브리지** — 데스크톱 매크로 버튼이 API 호출→결과 셀 기입.
  Office.js Range 쓰기 없이 다리 1·3 즉시 해소, xlam 하나로 배포. 현업형 최속 지름길
  (대가: 웹 엑셀 미지원).
- **B. 커스텀 함수 애드인 피벗** — `=VS.*` 함수군. 현업 정합 최대치, 단 별도
  런타임·번들 작업이 커서 분기급 과제.
- **C. 검증 게이트웨이 상품화** — "워크북 드래그 → 감사 리포트" 페이지 하나로
  audit/diff/린트를 리뷰어 제품으로 포장. 기술적으로 거의 완성, **포트폴리오 서사
  최강**("작성 도구"가 아니라 "심리·리뷰의 파이프라인화" = 회계사 관점).

**종합**: 개인 워크플로우는 §9 유지. 다음 확장 한 수는 Range 쓰기보다 **A(VBA 브리지)
실험 우선**, 대외 서사는 **C(게이트웨이 관점)**로 묶는다.

교훈 2줄 — 살아남은 현업 도구는 전부 "엑셀 대체"가 아니라 **"엑셀 기생"**이었다(접점은
작을수록 채택된다). 리뷰어 제품은 ISQM 증적을 만들어주므로 "편해요"가 아니라
**"안 쓰면 리스크"**로 팔린다 — 게이트 계보(비올 E·J, 모델러스 R·D) 문서화가 그 차별화 자산.
