# 웹 엑셀 애드인 2개 체제 UX — 시나리오·갭·로드맵

> 2026-08-01. 첫 실배포 sideload 실측 직후 작성. 질문: "내 DCF 엑셀 템플릿에서 시작해,
> Val-Studio 애드인으로 DART·PDF 사업보고서를 불러오고, Claude for Excel 과 왔다갔다하는
> 워크플로우 — **웹 엑셀 + 애드인 2개만으로 전 과정이 닫히는가?**"
> 결론: **지금(Level 1)은 사람이 다리 3개를 셔틀하면 되긴 하고, Office.js 배선(v1.2)으로
> 세 다리가 전부 사라진다.** 애드인 2개 아키텍처 자체는 올바른 종착지.

## 0. 전제가 되는 구조적 사실 2개

1. **애드인끼리는 직접 통신할 수 없다.** 각자 격리된 iframe, 크로스 애드인 API 없음.
   유일한 공유 매체 = **워크북 자체**(셀 + `_VS_STATE` 숨김 시트) + 클립보드 + 사람.
   → 기존 `_VS_STATE` 증적 설계(Claude 기록 → `excel/vs_state.py` 파싱)는 부가 기능이
   아니라 **유일하게 가능한 애드인 간 프로토콜**이다. 새로 발명할 것이 없다.
2. **역할 분담은 강제로 갈린다.**
   - Val-Studio Task Pane = **데이터 커넥터(BYOK)** + **결정론 계산·게이트(정본)**.
     Claude for Excel 은 BYOK 키를 들 수 없고 우리 API 를 못 부른다 → DART/ECOS 는
     반드시 Val-Studio 경유.
   - Claude for Excel = **워크북의 손**(셀 기입·수식·서사) + 판단 보조. 단 스크립트 실행
     불가 → 스킬은 "결정론 미검증" 지시문 모드(SKILL.md 이중 환경 규약). 검증은
     Val-Studio 로 돌아와야 닫힌다.
   - 사람 = 판단 + (당분간) 셔틀.

## 2. 표준 레이아웃 뉘앙스 (중요)

임의 템플릿은 표준 레이아웃이 아니므로 Val-Studio 4방향 중 **정적 감사만** 가능
(import·diff·중심셀 검산 불가). 해소 전략 = **표준 스파인 병설**: Claude for Excel 에게
템플릿 옆에 표준 `DCF` 시트를 병설시키면(스킬 W0 모드 C + promote 패턴) 임의 템플릿도
왕복 가능계로 들어온다. 원본 ↔ 표준 시트 대사는 CHECK 행으로.

또 하나의 프레임: "내 템플릿에서 시작"은 본질적으로 **평가인 UI 를 쓰는 감사인 트랙**이다
— 과거의 내 모델을 독립 재계산으로 대조하는 구조. 템플릿 신뢰가 아니라 검증이 기본자세.

## 3. 판정

- **Level 1(현재)**: 가능하되 다리 3개 수동. 한두 번은 되지만 루프 도구로는 부적합.
- **v1.2(Office.js) 후**: **전 과정이 2개 애드인 안에서 닫힌다.** 세 다리가 전부 Office.js
  하나로 해소되기 때문:
  - `Document.getFileAsync(Compressed)` → 현재 워크북 바이트를 그대로
    `/api/xlsx/audit·import·diff` 로 전송. **다운로드/업로드 셔틀 소멸, "검증" 버튼
    한 번으로 루프가 돎.** 서버 4방향 인터페이스 재사용 — 백엔드 변경 0.
  - Range 쓰기 → DART 숫자 `r_DART` 주입(다리 1), KPI·민감도 결과 기록(다리 3).
  - manifest 권한 `ReadDocument → ReadWriteDocument` 상향 필요(재업로드 필요).
