# 수출입은행 공공 API로 ValStudio 강화하기

작성일: 2026-10-04 (Asia/Seoul)

상세화: 2026-10-04. **구현용 명세는 [수출입은행 시장자료 상세 구현 계획](kexim_market_data_implementation_spec.md)에 정리했다.** 데이터 스키마·API 계약·Excel 기록/반영 절차·작업 의존성·검증 사례·운영 및 복구 기준을 포함한다. 이 문서는 목적·우선순위·공식 출처의 개요로 유지한다.

문서 성격: **강화 방향·구현 전 기준선**. 2026-10-05의 1차 구현 결과는 [구현·검증 기록](kexim_market_data_mvp_status.md)에 별도로 정리했다. 기업분석·채용 글은 사용자 정정에 따라 범위에서 제외한다. 현재환율·대출금리·국제금리 API 3개를 Excel 중심 ValStudio에 연결하고, 사용자가 지정한 공공데이터 활용 가이드북을 확장 범위 판단에 참고한다.

표기: `[확인]`은 계획 수립 때 읽은 코드·공식 명세·PDF의 내용, `[설계]`는 당시의 제안, `[가정]`은 일정·예시 입력, `[미확인]`은 실호출이나 추가 자료가 필요한 사항이다. **계획 수립 후 1차 코드를 구현했지만, 인증 데이터 API 실호출과 배포는 아직 하지 않았다.** 현재 구현 여부는 위 구현 기록을 기준으로 읽는다.

## 1. 강화 방향

**평가기준일의 환율·조달금리를 근거와 함께 워크북에 넣고, 평가인이 채택한 가정이 모델과 가치에 미치는 영향을 재계산한다.**

우선순위는 다음과 같다.

| 순서 | 추가 기능 | 사용자가 얻는 결과 | 범위 |
|---|---|---|---|
| 1 | 환율 원자료 수집·정규화·Excel 적재 | USD·JPY·EUR 등 환율과 기준일·출처가 연결된 입력 | 1차 MVP |
| 2 | 고정기준금리·국제금리 비교 | 차입 통화·만기·금리 종류에 맞는 조달비용 참고값 | 금리 응답 검증 후 |
| 3 | 환율·금리 시나리오와 독립 검증 | 매출·원가·차입비용·WACC·DCF 영향 및 오류 발견 | 기업 노출자료 확보 후 |
| 4 | 국가·산업·해외투자 자료 연결 | 해외사업·CAPEX·위험 가정을 뒷받침하는 근거 | 후속 확장 |

기존의 역할 분담을 따른다. **API는 관측자료를 공급하고, AI는 연결 근거를 제안하고, 평가인은 미래 가정과 적용 여부를 결정하고, 코드가 계산·대사를 수행한다.**

주의할 기존 간극: `MacroSheet.jsx`의 선택 지표는 CPI·GDP·임금이다. 백엔드에 환율 키가 있다는 사실만으로 Excel 환율 입력 기능이 완성된 것은 아니다. 기존 `/api/price/fx`는 값과 날짜를 반환하지만, 이번에 필요한 스냅샷·금리 종류·단위·공표 근거까지 담는 구조는 추가해야 한다.

상세화 과정의 추가 확인: `writeSheetPlan`은 기존 시트를 삭제·교체하며, `nav.js`는 Excel Task Pane에서 노출할 화면을 별도 제한한다. 또한 `_VS_FACTS`의 중복 생략은 동일 키·동일 값 기준이므로 출처만 바뀐 기록을 자동 보존하지 않는다. 따라서 `rMarket`에는 전용 행 추가 경로를 만들고, 관측 키에 스냅샷을 포함하며, `materials/market`을 Task Pane 허용 목록에도 등록하는 설계로 구체화했다.

## 3. 공식 API에서 확인한 범위

2026-10-04 공식 상세 페이지를 직접 HTTP로 열어 개발 명세를 읽었다. 검색 도구에서 일부 페이지가 열리지 않아 원사이트에서 확인했다. 문서 조회 성공은 인증 데이터 API 호출 성공을 뜻하지 않는다.

| API | 요청 경로와 코드 `[확인]` | 확인한 응답 의미 | 적용 경계 `[설계]` |
|---|---|---|---|
| [현재환율](https://www.koreaexim.go.kr/ir/HPHKIR020M01?apino=2&viewtype=C) | `oapi.koreaexim.go.kr/site/program/financial/exchangeJSON`, `AP01` | 통화코드, 매매기준율, 송금 받음·보냄 환율 등 | 평가용 기준값과 송금용 값을 목적별로 구분 |
| [대출금리](https://www.koreaexim.go.kr/ir/HPHKIR020M01?apino=3&viewtype=C) | `oapi.koreaexim.go.kr/site/program/financial/interestJSON`, `AP02` | `SFLN_INTRC_NM`: 대출기간, `INT_R`: 고정기준금리 | 특정 기업의 확정 대출금리·시장 회사채 수익률로 간주하지 않음 |
| [국제금리](https://www.koreaexim.go.kr/ir/HPHKIR020M01?apino=4&viewtype=C) | `oapi.koreaexim.go.kr/site/program/financial/internationalJSON`, `AP03` | SOFR 등 일별 국제금리. 통화·기간·금리 필드. CIRR 만기 구분 변경 공지 존재 | 응답에서 금리 종류·통화·만기를 식별한 뒤 목적에 맞게 연결 |

공통 요청변수는 `authkey`, `searchdate`, `data`다. 서비스별 명세에 일일 제한 1,000회가 표시되어 있다. 실제 제한이 키 전체에 합산되는지는 초기 실호출 단계에서 확인하며, 확인 전에는 합산 예산으로 운영한다. 결과 코드는 성공·데이터 코드 오류·인증 오류·일일 한도 소진을 구분한다.

공식 안내에 따라 **호출 도메인은 `oapi.koreaexim.go.kr`로 고정**한다. 기존 `www` 도메인의 API 병행 가동 종료일은 2026-04-30으로 안내되어 있다. [공공데이터포털의 도메인 변경 안내](https://www.data.go.kr/data/3068846/openapi.do).

환율 명세는 비영업일 또는 당일 11시 이전 요청에 `null` 반환을 안내한다. 최신값 요청과 과거 평가기준일 요청을 별도로 처리하고, 금리 API에도 동일한 시각 규칙이 있다고 추정하지 않는다.

### 반드시 먼저 해소할 미확인 항목

| 항목 `[미확인]` | 초기 확인 방법 | 미해소 시 처리 |
|---|---|---|
| 실제 응답의 통화·금리 종류·만기 목록 | 3개 API의 영업일 응답을 원사이트 조회값과 대조 | 값은 원자료로 표시하되 계산 입력 후보로 확정하지 않음 |
| 국제금리에서 SOFR·CIRR을 구분하는 방식 | 통화/기간 문자열과 홈페이지 설명을 대응. 별도 종류 필드는 명세에 없음 | `benchmark=unknown`, 자동 Kd 연결 차단 |
| 대출금리의 통화·대상 상품·가산금리 조건 | 공식 고정기준금리 설명 및 실제 응답 확인 | 일반 기업의 Kd로 연결 차단 |
| 금리 문자열의 표시단위 | 홈페이지 금리 표시와 API 숫자 대조 | 단위 불명 상태 유지. 무조건 `/100` 하지 않음 |
| 검색일과 실제 적용일·공표일의 관계 | 영업일·휴일·동일값 반복·금리 변경일을 비교 | 검색일을 검증된 관측일이나 공표일로 꾸며 기록하지 않음 |
| 조회 가능한 과거 범위·누락 패턴 | 평가기준일 주변의 소규모 날짜 표본으로 확인 | 장기 시계열을 제공한다고 약속하지 않음 |
| 새 API 키 발급 상태·재동의 조건·운영 환경 접근성 | 발급 화면과 로컬·Cloud Run 연결 확인 | 구현 준비 항목으로 남김 |

국제금리를 하나의 범용 무위험이자율로 취급할 수 없다. CIRR은 공식 지원 고정금리 수출신용의 최소금리라는 별도의 목적을 갖는다. [OECD 설명](https://www.oecd.org/en/topics/financing-terms-and-conditions.html). 국고채 Rf·베타·MRP·규모프리미엄은 이 API 3개만으로 해결되지 않으므로 기존 출처와 확인 절차를 유지한다.

## 4. 첫 구현: 환율 원자료와 기준일 검증

### 사용자 흐름 `[설계]`

1. 워크북의 평가기준일과 평가통화를 읽고, 누락 시 입력을 받는다.
2. 애드인의 `시장자료`에서 사용 통화와 조회 목적을 선택한다.
3. 요청 날짜의 원자료·정규화 값·검증 결과를 미리 보여준다.
4. `rMarket` 시트에 적재하고 `_VS_FACTS`에 관측 사실을 추가한다.
5. 스킬이 사용 목적에 맞는 관측값·미래 경로를 제안한다. 평가인이 가정을 확정하면 기존 모델 참조를 연결한다.
6. 쓰기 후 값을 다시 읽어 원자료·참조식·단위를 확인한다.

`rMarket`은 최초 생성 이후 행 추가 방식으로 유지한다. 채택값은 고정 주소를 가진 `MarketInputs`에 연결한다. 일반 시트 교체 함수를 기존 `rMarket`에 적용하지 않으며, 상세 명세의 부분 실패·재읽기·시트 소유권 규칙을 따른다.

처음 지원할 통화는 USD·JPY·EUR로 좁힌다. 나머지는 응답 통화 목록과 사용성을 확인하며 확대한다. 한 날짜 조회로 얻은 통화 배열을 공유해 통화별 중복 호출을 줄인다.

### 환율 적용 규칙 `[설계]`

- 평가시점 외화 잔액 환산에는 해당 기준일의 정책상 채택 환율을 사용한다. 이력·보고서상의 확정 원화 금액을 오늘 환율로 재작성하지 않는다.
- 기간 매출·매입 예측은 미래 환율 경로를 별도 가정으로 받는다. API 관측값은 출발 근거이며 미래 환율 예측치가 아니다.
- 과거 기간 평균이 필요하면 확보한 일별 시계열에서 계산하고, 관측 수·누락일·평균 방식을 함께 기록한다. 당일값을 연평균값으로 표시하지 않는다.
- `JPY(100)` 같은 표기는 **100단위 원자료와 1단위 정규화 값**을 함께 보존한다. `KRW/100 JPY`와 `KRW/JPY`를 서로 바꿔 쓰지 않는다.
- `DEAL_BAS_R`와 `KFTC_DEAL_BAS_R`, 송금 환율은 필드별 의미를 유지한다. 공급자나 필드가 바뀌면 기존 가정과의 차이를 표시한다.
- 기존 ECOS의 JPY 키는 원/100엔 레벨로 설명되어 있다. 새 공급자의 1엔 정규화 값을 그 키에 그대로 넣지 않는다.
- 휴일에는 사용자가 선택한 `직전 관측일` 정책으로 최대 7일 범위를 우선 탐색한다. `[설계 기본값]`이며 더 긴 공백에는 기간 확대를 요청한다. 요청일·채택일·간격·사유를 표시한다.
- 당일 11시 이전·장애·인증 실패를 휴일 결측과 구분한다. 이후 날짜나 다른 공급자의 값을 조용히 대체하지 않는다.

### 데이터 계약 `[설계]`

공통 항목:

`provider`, `dataset`, `requested_date`, `effective_date`, `effective_date_basis`, `published_at`, `fetched_at`, `currency`, `quote_unit`, `raw_value`, `normalized_value`, `value_unit`, `source_field`, `snapshot_id`, `payload_sha256`, `schema_version`, `findings`.

금리 추가 항목:

`benchmark`, `tenor_label`, `rate_type`, `day_count`, `rate_convention`, `effective_from`, `effective_to`.

`fetched_at`은 조회 시각이고 `published_at`은 공표 시각이다. 응답이나 다른 공식 근거가 없으면 공표 시각은 `null`로 남긴다. 명세의 날짜 검색 의미를 실제 값과 대조한 뒤 `effective_date_basis=validated_request_contract`처럼 날짜 근거를 명시한다. 엄격한 과거 평가 재현에 필요한 당시 공표 증거가 없으면 별도 경고·제한을 둔다.

`rMarket`은 관측자료 표, `_VS_FACTS`는 선택한 사실의 기록, `_VS_STATE`는 승인된 가정의 기록으로 역할을 유지한다. 사실 원장 키에는 날짜·통화·종류·만기·스냅샷을 포함해 서로 다른 관측이 최신 기록 하나로 소실되지 않게 한다.

## 5. 두 번째 구현: 조달금리와 차입비용

처음에는 **만기별 고정기준금리와 통화·종류별 국제금리 비교표**를 제공한다. DART 주석 또는 평가인 입력으로 회사의 차입 통화·고정/변동 여부·잔액·만기·가산금리·재설정 주기를 확보한 뒤 연결한다.

### 계산 경로 `[설계]`

```text
차입 약정·주석 + 종류를 확인한 기준금리 + 평가인이 확정한 조달조건
  → 차입건별 이자율·이자비용 및 만기/차환 시나리오
  → 평가통화·만기·한계조달조건을 확인한 세전 Kd 후보
  → 기존 WACC 조립기와 DCF 시나리오
```

- 변동금리 차입: 실제 약정의 지표 종류·재설정일·스프레드를 맞춘다. Overnight SOFR과 Term SOFR, 일별 관측값과 기간 복리금리는 별개다. 이름만 비슷하다고 대체하지 않는다.
- 고정금리 차입: 기존 약정 이자율은 시장금리 충격으로 즉시 바꾸지 않는다. 차환·신규 차입에 적용할 금리를 따로 둔다.
- CIRR/수출금융 기준금리: 해당 금융의 적용 조건을 확인한다. CIRR에 이미 포함된 구성요소와 별도 신용위험 비용을 구분해 동일 프리미엄을 중복 가산하지 않는다.
- 이자비용: 기본 계산은 기간 평균 잔액 × 약정상 유효 이자율 × 기간이다. 기준금리 조달 시나리오와 회계상 과거 이자비용을 구분한다.
- WACC Kd: 과거 평균 대출 이자율을 그대로 쓰지 않고 평가시점의 한계조달비용으로 타당한지 판단한다. 스프레드가 없으면 참고 금리만 보여준다.
- KRW FCFF에는 KRW와 일관된 할인율을 사용한다. USD 금리의 숫자를 원화 환산해 KRW Kd로 쓰는 규칙은 만들지 않는다. 외화 조달의 원화 헤지비용을 반영하려면 스왑·베이시스·헤지 조건 등 추가 자료가 필요하다.
- FCFF에는 차입 이자비용을 직접 중복 차감하지 않는다. 자금수지·3표의 이자 영향과 WACC 할인 효과를 분리한다. [FCFF 계산 근거](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/definitions.html).

## 6. 세 번째 구현: 기업 노출에 따른 시나리오와 감사

### 환율·금리에서 DCF까지 `[설계]`

```text
환율 관측 → 승인된 미래 환율 경로
  + 통화별 매출·매입·CAPEX·잔액·헤지 노출
  → 원화 매출/원가/CAPEX/운전자본 입력 재구성
  → 기존 FCFF 및 DCF 재계산

금리 관측 → 승인된 차환·조달 시나리오
  → 자금수지 이자비용 / 적격 Kd 및 WACC
  → 기존 시나리오 엔진으로 가치 영향 비교
```

국가별 매출과 결제통화별 매출은 다르다. 해외 매출 비중만 보고 전액 달러 노출로 설정하지 않는다. 주석의 외화 민감도도 화폐성 자산·부채 중심일 수 있으므로 미래 영업 노출 전체로 확대하지 않는다. 순노출·자연 헤지·파생상품 헤지·가격 전가·시차가 미확인인 항목은 자동값 대신 표시한다.

초기 출력은 `환율 단독`, `금리 단독`, `환율+금리 결합` 세 종류다. 시나리오별 매출·EBIT·FCFF·이자비용·WACC·EV·주당가치와 변동 근거를 비교한다. 가중치는 현재 시나리오 엔진처럼 평가인이 확정한 경우에만 사용한다. FX×금리 2차원 표는 후속 확장이며, 기존 WACC×영구성장률 표와 구분한다.

### 계산 예시 `[가정: API 실측값 아님]`

헤지·가격 전가가 없고 달러 매출 1,000만 달러, 달러 원가 400만 달러라면, 환율을 1,400원에서 1,540원으로 바꿀 때 단순 영업 순노출 영향은 `(1,000만 - 400만) × 140원 = 8.4억원`이다. 이는 세금·운전자본·CAPEX 반영 전 효과이며 기업가치 상승액을 뜻하지 않는다.

금리 4.0%에 약정 가산금리 150bp를 더한 예시 이자율은 5.5%다. 이 예시는 대상 회사의 실제 금리나 API 제공 금리라는 주장이 아니다.

### 제안하는 API 경계 `[설계]`

- `POST /api/market/kexim/quotes`: `dataset`(`exchange`/`lending`/`international`), `valuation_date`, `requested_date`, `date_policy`, `currencies`를 받아 관측·스냅샷·검증 결과를 반환한다. 상류의 요청 코드·URL은 서버 내부의 고정 대응표로 결정한다.
- `POST /api/market/kexim/sheet-plan`: 선택한 스냅샷으로 `rMarket` 쓰기 계획을 반환한다. 사실 원장 추가에는 기존 `/api/facts/append-plan`을 재사용한다.
- 프로젝트 기준일은 기존 `project.setup.valuation_date`를 정본으로 사용한다. 하위 모듈이 `base_date`를 요구하면 명시적으로 대응시키고, 빈값으로 검증을 생략하지 않는다.
- `/api/wacc/assemble`과 `/api/scenario`는 확정된 입력을 계속 소비한다. KEXIM 키나 원시 응답을 계산 엔진에 전달하지 않는다.

### 운영 방식 `[설계]`

- 키는 기존 BYOK 방식처럼 클라이언트에서 호출별 `X-Kexim-Key` 헤더로 전달하고 서버에 저장하지 않는다. 워크북·출처 URL·오류·로그에도 넣지 않는다.
- 상류 API는 쿼리 인증키를 쓰므로 전체 요청 URL/예외 문자열을 그대로 로그나 응답에 노출하지 않는다.
- 기본적으로 자동 반복 폴링 대신 평가기준일 조회와 명시적 갱신을 제공한다. 최신 환율 조회는 공식 당일 제공 시각을 고려한다.
- 자료 캐시는 데이터셋·요청일·스키마·값 스냅샷을 기준으로 관리한다. 과거 원본은 덮어쓰기보다 새 버전으로 남긴다. 같은 요청일의 응답이 바뀌면 차이를 표시한다.
- 일일 한도·중복 동시 요청을 관리한다. 인증 오류·코드 오류·한도 소진에는 재시도하지 않고, 일시적 네트워크 실패만 제한적으로 재시도한다.
- 신규 공급자로 전환해 기존 관측이나 확정 가정을 자동 교체하지 않는다. 이전값·새값·출처·기준일을 함께 보여준다.
- 자료 결측이 있는 스냅샷을 성공값으로 저장하거나, 오래된 캐시를 최신값으로 표시하지 않는다.

## 9. 구현 시 검증과 최종 완료 기준

이번 변경은 계획 문서이므로 기능 테스트를 실행하지 않았다. 구현 단계에서는 계산·단위·데이터 계약·Excel 연결을 검증하는 다음 테스트가 필요하다.

1. USD와 100단위 통화, 쉼표 숫자, 결측·비정상 응답을 정규화하는 표본 테스트. 금리 0과 FX 0은 의미가 다르며 일괄 결측 처리하지 않는다.
2. 결과 코드 오류·인증 실패·한도 소진·휴일·당일 미공표·이후 기준일 차단 테스트.
3. SOFR/CIRR 종류·통화·만기·표시단위가 없거나 불명확하면 Kd 연결이 차단되는지 확인.
