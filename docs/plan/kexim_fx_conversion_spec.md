# 외화 금액 환산 기능 — 구현 계약과 검증

작성일: 2026-10-05 (Asia/Seoul). 환율·금리 연동 PR의 추가 구현.

## 사용자 흐름

**자료·Brief → 환율·금리**에서 날짜·단위가 검증된 환율을 선택하고 원자료를 먼저 Excel에 기록한다. **외화 금액 환산**에서 Excel 선택 범위를 가져오거나 시트·범위를 입력한 뒤 원본 통화·금액 단위, 기존 출력 시트·시작 셀, 원화 출력 단위, 사유를 지정한다. 확인 체크 → 환산 미리보기 → 적용 순서로 진행한다.

한 번에 단일 통화의 연속 범위 최대 2,000셀·100열을 처리한다. 출력 범위는 원본과 같은 크기다. 숫자·0·음수·빈 셀을 지원하고 원본 값·수식을 수정하지 않는다. 빈 셀은 `IF` 수식으로 빈 결과를 유지한다. 출력 위치에는 값과 수식이 없어야 하며 원본과 겹칠 수 없다.

기간평균 환율·미래 환율 경로·외화끼리 환산·복수 통화 혼합 범위·회계상 환산손익 자동 분개는 이번 범위에 없다. 현재 함수는 사용자가 지정한 외화 금액과 관측 환율을 원화 금액으로 계산한다. 기간 매출이나 미래 추정에는 목적에 맞는 환율 가정이 별도로 필요하다.

## 수식과 단위

```text
원화 결과 = 원본 셀 × 원본 외화 배율 × 채택 환율 / 원화 출력 배율
```

| 선택 | 배율 |
|---|---|
| 외화 1단위 / 천단위 / 백만단위 | 1 / 1,000 / 1,000,000 |
| 원 / 천원 / 백만원 | 1 / 1,000 / 1,000,000 |

합성 예: 원본 `2`가 천 USD, 환율이 `1,400 KRW/USD`라면 백만원 결과는 `2.8`이다. JPY 원본 `JPY(100)=950`은 기존 수집기에서 `9.5 KRW/JPY`로 정규화하므로 환산 단계에서 다시 100으로 나누지 않는다. 이 예는 테스트 입력이며 공식 실응답 수치가 아니다.

출력 수식은 원본 셀과 `MarketInputs`의 고정 환율 셀을 참조한다. 값으로만 붙여넣지 않는다. 시트명에 작은따옴표가 있으면 Excel 참조 규칙으로 이스케이프한다. 단위를 바꾸거나 통화를 바꾸면 별도 채택 ID를 사용한다. 동일 통화·단위·원본/출력 위치에서 다시 채택한 환율은 해당 고정 입력에 연결된다.

원본이 텍스트 숫자·논리값·Excel 오류라면 중단한다. 숫자 범위 검증은 최종 결과와 중간 곱셈을 모두 확인하며 무한대·언더플로·Excel이 보관하지 않는 비정규화 수치를 차단한다. 관련 근거: [Microsoft 숫자 정밀도 설명](https://learn.microsoft.com/en-us/troubleshoot/microsoft-365-apps/excel/floating-point-arithmetic-inaccurate-result).

## API와 파일

`POST /api/market/conversion-plan`은 서버 저장 스냅샷을 복원해 현재 날짜 계약·평가기준일 정책을 재검증한다. 클라이언트의 임의 환율 숫자를 계산에 사용하지 않는다.

| 역할 | 파일 |
|---|---|
| 범위·금액·통화·단위 검증과 수식 계획 | `backend/excel/market_conversion.py` |
| 기존 단일 셀 연결과 공유하는 환율 채택 | `backend/excel/market_binding.py`의 `adoption_input_plan` |
| 조회 스냅샷 복원·계획 엔드포인트 | `backend/api/market.py` |
| 선택 범위 읽기·충돌 검사·쓰기·계산값 대사 | `frontend/src/marketBridge.js` |
| 환산 설정·미리보기·적용 | `frontend/src/pages/appraiser/MarketConversionPanel.jsx` |
| 화면 연결·저장 실패 재시도 | `MarketDataPanel.jsx`의 기존 공통 작업/저장 경로 |

요청에는 관측 ID·스냅샷 ID·조회 조건·현재 원자료/입력/사실 원장 격자, 원본/출력의 값·수식, 통화·단위·사유·확인을 포함한다. 원본·출력 시트는 기존 일반 모델 시트여야 한다. `_VS_*`, `rMarket`, `MarketInputs`, `Claude Log`는 환산 범위로 지정하지 않는다.

## 적용과 부분 실패

1. 적용 버튼에서 서버 날짜·스냅샷 계약을 다시 검증한다.
2. Excel 원자료·기존 입력·사실 원장, 원본과 출력의 값·수식을 다시 읽어 미리보기 조건과 대조한다. 병합 셀도 검사한다.
3. `MarketInputs`에 명시적으로 채택한 환율을 기록한다. 원본·출력·원자료를 다시 대조한 뒤 출력 수식을 쓴다.
4. 전체 재계산을 요청하고 원본 보존, 출력 수식·계산값, 채택 환율의 수식·값을 재읽기한다. 숫자는 상대오차 `1e-12`로 대사하며 0은 0과 일치해야 한다.
5. 대사 성공 후 `_VS_FACTS`에 환산 근거를 추가한다. 프로젝트 저장이 실패하면 기존 재시도 경로를 사용한다.

성공 근거에는 원본/출력 위치, 통화·단위, 적용일·환율·스냅샷, 사유, 원본 값/수식과 출력 값/수식의 해시를 남긴다. 한 사실 셀의 길이 제한을 지키기 위해 최대 범위의 금액·수식 전체를 사실 셀에 복제하지 않는다. 과거 원본 금액을 해시만으로 복원할 수는 없다. 과거 워크북의 재현에는 해당 워크북 버전 보관이 필요하다.

단일 작성자 환경이 대상이며 다중 시트의 원자적 롤백은 보장하지 않는다. 입력 기록 뒤 출력 쓰기에 실패하면 입력이 남을 수 있다. 출력 대사 뒤 사실 기록에 실패하면 출력 수식이 남을 수 있다. 화면의 마지막 완료 단계와 실제 셀을 확인한다. 출력 수식이 남은 범위는 새 미리보기에서 빈 범위 조건으로 차단되므로 확인 없이 덮어쓰지 않는다.

병합 검사에는 [ExcelApi 1.13의 범위 API](https://learn.microsoft.com/en-us/javascript/api/excel/excel.range?view=office-js#excel-excel-range-getmergedareasornullobject-member(1))가 필요하다. 지원하지 않는 호스트에서는 쓰기 전에 중단한다.

## 검증 범위

합성 API·로컬 파일 기반 백엔드와 가짜 Office 어댑터로 단위 변환, JPY 배율, 작은따옴표 시트명, 최대 범위의 근거 크기, 통화 불일치, 중첩 범위, 기존 출력 값/수식, 비숫자, 날짜 계약 철회, 원본·출력 변경, 병합·보호된 시트, 잘못된 계산값, 사실 기록 실패를 검증했다. 누적 실행 결과는 [구현·검증 기록](kexim_market_data_mvp_status.md)을 기준으로 본다.

**실제 API 응답과 Excel 호스트 인증은 미실행이다.** 실제 키와 날짜 근거를 확보한 뒤 워크북 복사본에서 선택 범위 → 미리보기 → 적용 → 재열기, 수동 계산·보호·병합·공동편집·부분 실패를 검수해야 한다. 코드 검토 준비 상태와 운영 검수 완료를 구분한다.
