### 1-2. 3자 역할은 이미 강제로 갈려 있다

[SKILL.md](../../.claude/skills/excel-valuation-workbook/SKILL.md) 의 **역할 3분할**이 지배 규약이다:

> **제안(Claude) → 판단(평가인) → 검증(결정론 코드). 이 순서를 절대 뒤섞지 않는다.**

여기에 [addin_two_panel_ux.md §0](addin_two_panel_ux.md) 의 구조적 사실 2개가 겹친다:

- **애드인끼리 직접 통신할 수 없다** — 각자 격리 iframe, 크로스 애드인 API 없음. 공유 매체는 **워크북 + 클립보드 + 사람**뿐.
- Claude for Excel 은 **BYOK 키를 들 수 없고**(DART/ECOS 불가), **스크립트 실행이 불가**하며(SKILL.md "지시문-only 폴백" = 산출물에 "결정론 미검증" 라벨), 웹검색도 없다(MCP 커넥터·사용자 업로드만).

→ **패널 에이전트의 정당한 영역 = 키가 필요하고 + 결정론 게이트가 이미 붙어 있고 + 그 사이에 판단이 낀 자리.** 세 조건 동시 성립이 판정 기준이다.

### 1-3. 애드인 간 프로토콜은 이미 타입이 있다 (MAS 논의의 핵심)

`backend/excel/vs_state.py` 가 읽는 `_VS_STATE` 시트 = **유일하게 가능한 애드인 간 통신 규격**이며, 이미 구조화돼 있다:

| 요소 | 실측 |
|---|---|
| 가정 대장 5열 | `_LEDGER_COLS = ["name", "value", "source_type", "basis", "approval"]` (vs_state.py:26) |
| 미승인 격리 | `_UNAPPROVED = "suggested"` — source_type 이 suggested 인데 approval 이 빈칸/미승인/pending 이면 경고 (vs_state.py:28·122) |
| 방향 | 웹은 **읽기 전용 이관**만, 되쓰기는 스킬·평가인 몫(역할 3분할) |
| 자유형식 로그 | `Claude Log` 시트 — 턴별 서술, 순서만 보존 |

⭐ **이 구조가 곧 에이전트 안전장치다.** 에이전트 제안을 `source_type=suggested` 로 기록하면, **이미 존재하는 미승인 게이트가 자동으로 "승인 없이는 하류로 못 흐른다"를 집행**한다. 에이전트 출력의 격리 구역을 새로 발명할 필요가 없다.

## 2. MAS 판정 — 필요 없다 (3중 근거)

### 2-1. 구조적: 어떤 MAS도 blackboard 로 퇴화하고, blackboard 는 이미 있다

오케스트레이션형 MAS(플래너-워커 fan-out, 에이전트 간 메시지 패싱)는 **에이전트끼리 대화할 수 있어야** 성립한다. 그런데 이 토폴로지에서는 그게 API 수준에서 봉쇄돼 있다(§1-2). 워크북을 매개로만 통신하는 순간 그건 **blackboard 아키텍처**이고, 그 blackboard 의 스키마·승인 세마포어는 §1-3 대로 이미 구현돼 있다.

즉 **MAS 를 도입한다는 것은 조정층을 새로 만드는 일인데, 만들 조정층이 이미 존재한다.** 새로 얹으면 정본이 둘이 되고, §7-1 이 경고한 "정본 분기(fork)"가 조정층에서 재현된다.

### 2-2. 경제적: 검증이 싼 도메인에서 fan-out 은 진다

다관점 fan-out 이 이기는 조건은 **탐색 공간이 넓고 + 검증이 비싼** 문제다. 이 도메인은 정반대다:

| | 일반 MAS 가정 | 이 도메인의 실제 |
|---|---|---|
| 검증 비용 | 비쌈 → 여러 에이전트 투표로 대체 | **결정론 게이트가 즉시·공짜로 채점** (대사 차이 0, tie-out FAIL 0, per_share 불변) |
| 판정 권위 | 다수결 | **게이트가 정본** — 에이전트 3인이 동의해도 대차가 안 맞으면 오답 |
| 실패 모드 | 놓침(false negative) | 그럴듯한 오답이 통과하는 것 — 투표는 이걸 **악화**시킨다(같은 편향 공유) |

`checks.py` 29종 + ingest 4종 tie-out + excel 정적감사가 이미 "다관점 심리"의 역할을 결정론으로 하고 있다. **단일 에이전트 제안 + 게이트 반증**이 압도적으로 싸고 정확하다.

### 2-3. 그래도 병렬이 이득인 3곳 — 전부 MAS 가 아니다

| 자리 | 필요한 형상 | MAS 인가 |
|---|---|---|
| 계정분류 수백 건 × 5개년 | 동일 에이전트 **map**(조정 0, 결과 합쳐 대사 1회) | ❌ 단순 병렬화 |
| peer 후보 83사 Step2 판정 | 동일 에이전트 **map** + 퍼널 reduce | ❌ 단순 병렬화 |
| 게이트웨이 배치 심리(§10-2 형태②) | 워크북 N개 병렬 심리 → 리포트 | ❌ 서버측 배치, 패널과 무관 |

**결론: 패널 안에 MAS 는 불필요.** 필요한 병렬성은 조정이 없는 map-reduce 이며, 이는 오케스트레이터 없이 `parallel` 호출 하나로 끝난다. 진짜 다관점 심리가 필요해지는 시점은 게이트웨이 상품화(형태 ②)로 넘어갈 때이고, 그건 패널이 아니라 서버 배치 트랙의 과제다.

## 5. 패널이 Claude for Excel 역할을 흡수해야 하나

### 5-1. 판정: 전면 흡수 아니오 / 부분 흡수는 이미 진행 중

기술적 장벽은 사실 낮다 — **"셀에 쓰는 손"은 이미 우리 패널에 있다**: `writeToSelection`(선택 셀 표 기입) · `writeSheetPlan`(시트 생성 + **수식** 기입) · `writeFormula`(주소 지정 수식). 그러니 문제는 "할 수 있나"가 아니라 **"어디까지가 우리 것인가"**다.

### 5-2. 경계 규칙 (§2 MAS 판정과 같은 뿌리)

> **에이전트 산출물을 결정론이 채점할 수 있으면 Val-Studio 패널, 없으면 Claude for Excel.**

| 우리 것 (채점 가능) | Claude for Excel 것 (채점 불가) |
|---|---|
| 계정분류 → 대사 차이 0 | 임의 템플릿 자유 조작 |
| Step2 판정 → 퍼널 + 사유 필수 | 사용자 의도의 자유 해석 |
| 주석 카테고리 → tie-out | 서식·차트·표 미화 |
| 셀맵 → 산술 지문 | 임의 질의응답·설명 |
| findings 수정플랜 → 재감사 | 워크북 전반의 잡무 |
| 서사 → 린트 5종 | 정형 없는 시트 정리 |

### 5-3. 전면 흡수가 잃는 것 3가지

1. **보안 경계 — 법인 채택의 유일한 관문.** 현재 `getFileAsync` 는 워크북 바이트를 **우리 서버의 결정론 처리**로 보낼 뿐, 제3자 LLM 에 보내지 않는다. 전면 흡수는 워크북 내용을 LLM 프로바이더로 흘리는 것을 의미하고, 이는 §10-1 의 "클라이언트 데이터 외부 SaaS 반출 원칙 금지"에 정면으로 걸린다. BYOK·서버 시크릿 0 설계의 이점이 사라진다.
   → **도출되는 설계 원칙: 에이전트에 보내는 페이로드는 워크북 전체가 아니라 게이트가 좁혀준 최소 조각이어야 한다.** (계정명 리스트 / peer 후보 개요 / finding 1건 + 해당 셀 근방) 이건 보안 논거인 동시에 정확도 논거다.
2. **강점과 무관한 영역에서의 경쟁.** 임의 워크북 이해·자유 셀 조작은 우리 해자(결정론 게이트·BYOK 커넥터·지식층 49챕터·규칙 계보)와 무관하다. 그 영역에서 Anthropic 의 1st-party 제품과 겨루는 것은 자원 배분 실패다.
3. **패널 슬롯.** `nav.js:71-89` 가 EMBED_ALLOW 를 4축으로 깎으며 명시한 이유가 "**패널 슬롯을 Claude for Excel 과 나눠 써야 한다**"였다. 350px 에서 범용 채팅 에이전트를 돌리면 브리지 4축이 밀려난다.

### 5-4. 재검토 트리거 (미실측 의존)

[addin_two_panel_ux.md §4-④](addin_two_panel_ux.md) 의 **"웹 엑셀 Task Pane 2개 동시 표시 가능 여부"가 아직 미실측**이다. 이 결과가 아키텍처 결정을 가른다:

- **동시 표시 가능** → 위 분업이 그대로 최적. 흡수 불요.
- **전환식(하나만 표시)** → 사용자가 매 루프 패널을 갈아끼워야 하므로 **흡수 압력이 실제로 발생**한다. 이 경우에도 답은 전면 흡수가 아니라 **"채점 가능한 셀 조작의 범위를 넓히는" 부분 흡수**(=우선순위 3·4번을 앞당김)다.

**→ 이 실측 1건이 후속 설계의 선행 조건이다.** 우선순위 3·4 착수 전에 확인할 것.

## 6. 에이전트 형태 규약 (어떤 후보든 공통)

1. **패널 UI 는 채팅창이 아니라 "제안 카드"** — 제안 + 근거(provenance/인용) + 승인/거부/수정 버튼. 350px 에서 대화는 성립하지 않고, 무엇보다 **대화는 증적이 안 남는다.**
2. **출력은 자유 텍스트 금지, 기존 dataclass 로만** — `Step2Judgment` · `ClassifyHint` 등 이미 있는 타입으로 받아 결정론 함수의 입력으로 넣는다. 에이전트는 코드를 대체하지 않고 **사람의 판단을 초안화**할 뿐이다.
3. **사유 없는 판정 거부를 전 영역 표준으로** — 지금은 `peer_selection.py:200` 에만 있는 규약이지만, 이것이 사실상 에이전트 도입의 안전 표준이다("감사 방어 불가"라는 거부 사유가 그대로 일반화된다).
4. **provenance 필수** — `ExtractMethod` 에 LLM 경로를 추가하고 confidence 를 부여, `merge_confidence` 의 약한고리 최소값 규칙에 그대로 태운다. 에이전트가 낀 값은 자동으로 신뢰도가 낮아진다.
5. **`source_type=suggested` 로 `_VS_STATE` 에 기록** — 미승인 게이트가 하류 유출을 자동 차단(§1-3).
6. **페이로드 최소화** — 게이트가 좁힌 조각만 전송(§5-3-1).

## 11. 구현 기록 — 판정 배관 + W5 Step2 (2026-08-04)

### 11-1. 파일 지도

| 파일 | 역할 |
|---|---|
| `backend/agent/registry.py` | 모델 SSOT — id·단가·컨텍스트·`supports_effort` + `PRICING_VINTAGE` |
| `backend/agent/judge.py` | `judge()` 실행기 + `check_shape()`(JSON Schema 부분집합 재검사) |
| `backend/agent/providers/base.py` | `ProviderReply` / `ProviderError(kind)` |
| `backend/agent/providers/anthropic_client.py` | 공식 SDK 어댑터(lazy import) |

| `backend/api/main.py` | `GET /api/agent/models` · `POST /api/peer/judge` |

계층: `agent/` 는 **자산 무의존**(peer 도 워크북도 모른다) — calc_core 가 IO 를 모르는 것과
동형. 스키마·프롬프트는 그 dataclass 를 소유한 도메인 모듈 옆에 둬 스키마 드리프트를 막는다.

### 11-2. 설계 결정 4가지 (근거 포함)

1. **초안이지 실행이 아니다.** `/api/peer/judge` 는 판정 표를 채울 뿐 퍼널을 돌리지 않는다.
   확정은 사람이 `/api/peer/select` 를 눌러야 일어난다 — §6-1 제안 카드 규약의 구현.
2. **프로바이더 폴백 금지.** 실패 시 다른 모델로 갈아타지 않는다(추측 금지). 서버사이드
   `fallbacks` 도 채택하지 않았다 — 조용한 모델 전환은 "무엇이 판정했나"를 흐리고,
   사용자가 고른 모델을 서버가 뒤집는다. 대신 `stop_reason=="refusal"` 을 명시 처리.
3. **사유 없는 판정은 버린다(지어내지 않는다).** 버려진 자리는 '판정 없음' 이 되어
   사람이 채워야 하고, 그때까지 `select_peers` 의 ValueError 게이트가 그대로 선다.
4. **프로바이더의 strict 를 믿지 않는다.** 같은 스키마로 `check_shape` 가 한 번 더 본다
   (공급자마다 강제 방식이 달라 "강제했다"를 믿으면 드리프트가 조용히 통과한다).

### 11-3. 구현 중 잡은 함정 3가지

- **티커 표기**: `select_peers` 의 판정 매칭은 정규화 없는 **정확일치**다. 모델이
  `A145020` 으로 답하면 후보 `145020` 과 안 맞아 "판정 누락"으로 조용히 거부된다 →
  매칭은 `normalize_ticker`, 반환은 **원본 후보 문자열**로 고정(회귀 테스트 있음).
- **Haiku 4.5 는 `effort` 를 받으면 요청이 거부된다** → `Model.supports_effort` 플래그로
  표에 사실을 박고 어댑터가 자동으로 떨군다. 모델 선택 기능을 붙이는 순간 생기는 함정.
- **현행 모델은 `temperature`/`budget_tokens` 자체가 제거**됐다(400). 온도로 결정론을
  살 수 없다 → 재현성은 provenance(모델·프롬프트 해시)와 게이트 채점으로만 확보된다.

### 11-4. 잔여
