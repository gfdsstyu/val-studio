작성일: 2026-10-05 (Asia/Seoul). 대상: 로컬 `D:\valuation-platform` 작업 트리. 배포하지 않음.

상위 문서: [강화 계획](kexim_market_data_integration.md), [상세 구현 명세](kexim_market_data_implementation_spec.md).

## 1. 이번에 구현한 범위

자료·Brief에 **환율·금리** 탭을 추가했다. 일반 웹과 Excel Task Pane에서 같은 메뉴를 사용한다. BYOK 설정에 한국수출입은행 키를 추가했고, 기존 BYOK 방식대로 브라우저 localStorage에 보관하고 호출 시 `X-Kexim-Key` 헤더로 전달한다. 서버는 인증키를 프로젝트·스냅샷·워크북에 기록하지 않는다.

현재환율·대출금리·국제금리의 공식 `oapi` 경로를 고정해 수집한다. 인증 실패와 한도 초과는 즉시 종료하고, 네트워크 오류는 최대 3회 시도한다. 조회 정책은 정확한 날짜 또는 최대 7일 이전 탐색이다. 인증·서버 오류를 빈 날짜로 취급하지 않는다.

환율은 USD·JPY·EUR를 지원한다. `JPY(100)` 원본 950은 원문을 보존하면서 `KRW_per_1_JPY = 9.5`로 정규화한다. 결측·단위 미상·0 이하 환율·미래 자료를 모델 입력으로 채택하지 않는다. 대출금리·국제금리는 원문 값과 종류/만기 라벨을 표시하지만 단위·벤치마크 분류가 확인되지 않았으므로 모델 입력에 연결하지 않는다.

원본 바이트와 정규화 스냅샷을 `var/market/kexim/`에 저장한다. 같은 원본은 같은 식별자를 사용하고 변경 응답은 이전 스냅샷을 유지한 채 새 식별자를 만든다. 복원 시 정규화 파일과 원본 해시를 대조한다. 원자료와 조회 결과의 적용 가능성을 분리해 평가기준일·엄격 모드를 바꿔도 저장 원본을 수정하지 않는다.

Excel 기록은 새 `marketBridge.js`를 사용한다. 기존 시트 교체 함수는 호출하지 않는다. `rMarket`에 행을 추가하고 `_VS_FACTS`에 관측별 `suggested` 사실을 남긴다. 채택은 사용자가 대상 셀·단위·평가기준일·사유를 확인한 후 수행한다. 원자료 → `MarketInputs` 고정 셀 → 모델 셀의 수식을 만들고 재계산 값과 수식을 재읽기한 뒤 채택 사실을 추가한다. 미리보기 이후 원자료·입력·사실 격자나 대상 셀이 변경되면 중단한다.

**첫 MVP의 운영 검수 완료를 뜻하지 않는다.** 날짜 대응 근거가 미검증인 기본 설정에서는 자료 조회·원자료 기록까지 가능하고 모델 반영은 차단된다. 인증키가 없어 공식 응답 검증은 `not_run`이다. 실제 Excel 호스트에서 쓰기·수식 재계산·되읽기는 별도 검수해야 한다.

## 3. 실행 방법과 설정

```powershell
py -3.12 -m uvicorn backend.api.main:app --reload
```

프런트 개발은 `frontend`에서 `npm run dev`. 일반 빌드는 `npm run build`. 새 프로젝트의 평가기준일을 먼저 지정하고 BYOK 키 저장 후 **0. 자료·Brief → 환율·금리**에서 조회한다. 평가기준일이 없는 기존 골든 프로젝트에서는 조회 버튼이 비활성화된다.

| 환경변수 | 기본값·의미 |
|---|---|
| `FEATURE_KEXIM_MARKET_DATA` | 로컬 `1`, `K_SERVICE`가 있는 호스팅 `0`. `1`만 활성화 |
| `KEXIM_SNAPSHOT_DIR` | `<repo>/var/market/kexim`. `var/`는 Git 제외 |
| `KEXIM_DATE_CONTRACT_FILE` | 미지정 시 모든 자료의 검색일→적용일 관계 미검증 |
| `KEXIM_API_KEY` | 실호출 점검 스크립트 전용. 웹 조회는 BYOK 헤더 사용 |

인증키를 환경에 준비한 뒤 다음 명령으로 응답을 비공개 로컬 저장소에 보존할 수 있다. 날짜는 실제 비교할 평일·휴일·최근일로 바꾼다.

```powershell
py -3.12 scripts/kexim_probe.py --date 2026-10-02 --date 2026-10-03 --dataset all
```

현재 실행 결과는 `{"status":"not_run","reason":"KEXIM_API_KEY not configured"}`였다. 점검 스크립트는 인증정보를 출력하지 않으며 응답을 받더라도 날짜 검증을 자동 승인하지 않는다. `live_response`는 수신 사실을 뜻하며, 적용일·단위 대사 완료인 `live_pass`와 다르다.

날짜 계약 활성화는 실제 표본을 공식 게시 자료와 대조하고 검증 기록을 남긴 후 수행한다. 설정 파일에는 API별 `verified: true`, 읽을 수 있는 근거 위치 `evidence`, 변경된 규칙 버전 `version`을 넣는다. 근거 파일 존재·내용의 진위를 코드가 독립 인증하지는 않는다. 허위 또는 단순 MOCK 근거로 운영 설정을 활성화하면 안 된다. 설정 변경 후 서버를 재시작하고 자료를 새로 조회한다. 설정 예시는 형식 설명이며 활성화된 운영 설정이 아니다.

```json
{
  "exchange": {
    "verified": true,
    "evidence": "실제 대사 기록의 경로와 표본 날짜",
    "version": "실검증 후 부여한 새 버전"
  }
}
```

검색일 대응을 검증해도 공표·개정 이력을 입증한 것은 아니다. 현재 `strict_snapshot`은 공표 이력이 없어 계속 모델 반영을 차단한다.

## 6. 상세 명세 대비 구현 선택과 남은 제약

- 로컬 사용을 위해 기능 플래그는 로컬 기본 활성화, Cloud Run 기본 비활성화로 정했다. 기능 비활성화가 기존 Excel 수식·자료를 삭제하지 않는다.
- 스냅샷 저장 경로는 새 `.cache` 대신 이미 Git 제외된 `var/market/kexim`을 사용했다. GCS 프로젝트 저장 설정과 시장자료 영속 저장은 별개다. Cloud Run의 시장자료는 현재 `ephemeral`로 표시한다.
- 호출 예산 900은 보수적인 **프로세스 내부 정책**이다. 공급자의 1,000회 제한이 API별/키별 합산인지 또는 몇 시에 초기화되는지 실검증한 값이 아니다. 내부 카운터는 KST 날짜별이며 서버 재시작·복수 인스턴스에 걸쳐 합산하지 않는다.
- 정상 과거 캐시는 24시간, 오늘 자료·무자료 캐시는 5분 유지한다. `cache_only`는 저장된 관측을 사용하며, 알 수 없는 날짜를 무자료로 간주해 건너뛰지 않는다. `refresh`는 의도한 신규 조회라 동시 새로고침을 합치지 않는다. 일반 조회는 프로세스 잠금으로 캐시 미스를 합친다.
- Excel 작업은 단일 작성자 환경을 대상으로 한다. 모든 시트 변경의 원자적 롤백·공동편집 잠금을 보장하지 않는다. 중간 단계 실패 시 화면의 마지막 완료 단계와 셀을 확인한다. 원자료 기록 재시도는 관측 ID로 중복을 건너뛴다. 모델 반영 도중 실패했다면 대상·채택 셀을 확인하고 변경 내용을 다시 미리본다.
- 대상 셀은 사용자가 지정한다. 기대 단위와 워크북 평가기준일은 사용자 확인 사항이며 템플릿에서 자동 추출·증명하지 않는다. `MarketInputs`/대상 값만 대사하며 전체 DCF 가치 재계산 시연은 KX10에 남아 있다.
- 원자료의 열 순서 변경은 이름으로 대응한다. 사실 원장은 기존 작성 함수가 고정 열 순서를 사용하므로 현재 기본 순서와 다르면 차단한다. 값을 잘못된 열에 기록하면서 성공 처리하지 않는다.
- `MarketInputs`의 행은 대상 시트·셀별 고정 주소다. 이미 해당 입력을 참조하는 모델에는 사용자의 명시적 재채택 시 새 환율이 전파된다. 단순 조회나 원자료 추가는 채택 수식을 바꾸지 않는다.
- 승인 사실 기록은 수식·값 대사 이후에만 수행한다. 사실 기록 실패나 프로젝트 저장 실패는 셀 쓰기 실패와 구분해 표시한다. `_VS_STATE`·`Claude Log`에는 쓰지 않는다.
- 로컬 서버의 스냅샷이 사라지면 기존 워크북 수식/숫자는 유지되지만 새로운 서버 채택 계획은 만들지 않는다. 워크북만으로 서버 원본을 공식 스냅샷으로 역생성하는 기능은 아직 없다.

## 7. 다음 검수 순서

1. 실제 키로 평일·휴일·당일 오전/오후 응답을 수집하고 공식 환율 화면과 USD·JPY·EUR를 대조한다. 세 API의 result/필드/공란/단위를 각각 기록한다.
2. 날짜 근거가 확보된 API만 계약 설정을 활성화하고 새 스냅샷을 만든다. 국제·대출금리의 매핑이 해결되지 않으면 계속 표시 전용으로 둔다.
3. Excel 복사본에서 원자료 추가·재실행·수정 충돌·보호된 시트·수식형 문자열·수동 계산 모드를 검수한다.
4. 모델의 실제 환율 입력 단위와 기준일을 확인하고 명시적 채택 → 입력·수식 대사 → 전체 모델 재계산을 수행한다. 실패 후 재시도·프로젝트 재열기까지 기록한다.
5. 위 증거가 모였을 때 KX07~10을 완료로 바꾼다. 이후 금리 조건·노출 시나리오와 Cloud Run 영속화 단계로 진행한다.
