# DCF 모델링 실무 (MSVALUE 2강·4강)

출처: `강의자료\(MSVALUE) 2강/4강 강의자료.xlsx`. 모델 구성·매출추정·Finalize 실무.
우리 `calc_core` 상류(revenue·ebit·fa·wc) + 웹 UI 워크플로우 근거.

---

## 1. 매출추정 2방식 (4강 모델링 보완)

### 방식 A. 성장률 기반 (top-down 근사)
```
매출액 = 전기 매출액 × (1 + 성장률)
```

### 방식 B. Bottom-Up (P × Q) — 사업구조별 driver 사전
```
매출액 = Quantity(Q) × Price(P)
```
| 사업 유형 | Q (수량 driver) | P (단가) |
|---|---|---|
| 제조/부품 | 판매량 | 판매단가 |
| **구독 서비스** | 고객수 | **ARPU** (Average Revenue per User) |
| **웹툰/콘텐츠** | 결제고객수 | **ARPPU** (per Paying User) |
| **공간(리테일)** | 점포 수 | 점포 당 매출액 |
| **수주(프로젝트)** | 수주건수 | 프로젝트 별 매출액 |

> → `revenue.RevenueNode` 리프의 **실무 유형 사전**. 웹 트리 UI에서 사업유형 선택 시 Q/P 라벨·단위 자동 세팅.

### 매출추정 4방식 (사업계획서 관점 — 블로그 보강)
| 방식 | 적용 상황 |
|---|---|
| **시장규모·점유율** | 시장이 명확히 정의되고 경쟁자 정보 확인 가능(시장성장률×점유율) |
| **수량·단가(P×Q)** | 가장 일반적 — 수량 증가율·단가 상승률 개별 추정 후 결합 |
| **마일스톤 접근** | 초기 스타트업(수익 미실현) — 단계별 달성확률 × 기대매출 |
| **시나리오 분석** | 성공/실패·낙관/중립/비관 확률 설정, 시나리오별 P·Q |
- 합리적 추정 = 거시경제 + 시장 경쟁구조 + **회사 공급능력** 종합.

### 원가추정 4요소 (블로그 보강)
- **인건비**: 인원계획×급여수준(노동법 제약 고려). **변동·고정비**: 통계분석·산업이해로 구분
  (고정비는 매출 비동인). **재료비**: 물량×단가(원자재 변동성). **감가상각**: 기존자산 vs 신규 CAPEX
  분리, 절세효과 반영. → **원가동인(cost driver)** 파악 + 회피가능성·지속성 검토.

### 세부구분의 실익 (구분 정당성)
제품군 세분은 아래 **차이가 있어야** 의미:
- **성장률 차이**: 세분 제품군 성장률이 다를 때만 구분 실익(같으면 합산과 동일 — 4강 예시로 증명).
- **마진 차이**: 제품군별 GP%/원가율 상이.
- **운전자본 차이**: 회전율 상이.

> `revenue.validate_tree_sums` + "구분 실익" 가이드: 하위노드 성장률·마진이 동일하면 상위로 합치도록 UI 권고.

## 2. 모델 구성 (2강 STEP + 4강 시트)

```
STEP0 평가대상 리서치 → STEP1 FS정리 → STEP2 DCF골격 → STEP3 WC
STEP4 EBIT(매출·원가·판관비) + BackData → STEP5 FA·상각비
```
4강 시트: Assumption · DCF · EBIT · FA · WC(오류수정) · WACC · H_FS · BackData · 상각비계산 · 유사회사FS.

---

## 3. 모델 Finalize 체크리스트 (4강) — 연결 검증

**Dummy 제거 + 시트 간 연결 확인** (우리 calc_core 모듈 의존성과 일치):

| 대상 | 계정 | ← 원본 시트 |
|---|---|---|
| DCF | 매출액·매출원가·판관비 | ← EBIT |
| DCF | (+)DEP · (−)CAPEX | ← FA |
| DCF | ΔWC | ← WC |
| DCF | 비영업자산·이자부부채 | ← FS정리 |
| DCF | WACC | ← WACC |
| EBIT | 상각비(원가)·상각비(판관비) | ← FA |
| WC | Driver(매출·원가) | ← DCF/EBIT |

### 핵심 주의
- **TV = 추정기간말 FCFF × (1 + PGR)** / (WACC − PGR) — terminal 성장 적용 셀 확인.
- WC 서식 오류(1주차) 수정 필요 — 회전율 방향.
- 최종: Dummy 값 제거 → 가정 근거 요약 → 서식 정리.

> → 우리 `model.run_model` 의 모듈 조립 순서·연결이 이 체크리스트를 코드로 강제(assert). 웹 UI는 "연결 상태 OK 체커"로 시각화.
