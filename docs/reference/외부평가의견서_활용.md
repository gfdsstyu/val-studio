# DART 외부평가기관 평가의견서 — 활용 설계

`D:\Valuation\외부평가의견서\` = **실제 DART 공시된 공인 평가기관의 외부평가의견서** 13건.
자본시장법상 합병·자산양수도·주식양수도 시 필수 공시되는 **공식 평가 산출물**.

> 참고보고서(증권사 애널리스트)와 **역할이 근본적으로 다름**:
> - 참고보고서 = 매수/투자 관점, 목표주가, 컨센서스 → 가정 *근거*.
> - 외부평가의견서 = 공인 평가기관의 *공식 의견*(DART 공시) → **산출물 양식 정본 + 감사인 트랙 대상**.

---

이 의견서 PDF들은 **스캔 이미지(텍스트 레이어 0자)**. `pdftotext` 추출 불가 확인됨.

OCR 경로 추가(감린이 `kordoc` HWP/PDF→md 벤치마킹). OCR 후 표 재구성 + 4종 검증.

### 평가방법론 분류 (taxonomy)
| 방법론 | 성격 | 사례 | 우리 엔진 |
|---|---|---|---|
| **DCF법 (수익가치)** | 현금흐름할인, 계속기업 | 11/13건 (지배적) | ✅ `calc_core` |
| **시장접근법 (상대가치)** | 유사기업 배수(PER/EV/EBITDA) | 이노테라피(병행) | 확장(comps) |
| **조정순자산법 (자산가치)** | 순자산 공정가치 | 이노테라피(병행, 투자조합) | 확장 |
| **이항모형/OPM (옵션가치)** | 신주인수권·전환권·옵션성 | 롯데케미칼(병행) | 확장 |

> **핵심 패턴**: 비상장 타법인주식양수 = **DCF법이 기본**. 자산성(투자조합)·옵션성(신주인수권)이 있으면 보조 방법 **병행**. 평가법인 분포: 회계법인 6 · 회계법인 4 · 한영 2.
> → report 템플릿의 **방법론 선택 로직**(대상 성격 → DCF±보조) + 감사인 트랙 "방법 적정성" 테스트 기준.

## 2. 활용 (3대 역할)

### ① 산출물 양식 정본 (report template)
우리가 생성하는 **평가의견서의 실제 공시 양식**. 표준 구조:
```
1. 평가의 개요 (평가목적·평가기준일·평가대상)
2. 평가기관의 독립성·적격성
3. 평가대상회사 개요 (사업·연혁·지배구조)
4. 평가방법의 선정 (DCF/시장가치/본질가치 + 선정 근거)
5. 주요 평가가정 (추정기간·매출·원가·WACC·영구성장률)
6. 평가결과 (EV→지분가치→주당가치)
7. 민감도 분석
8. 평가의 한계 및 유의사항
```
→ `export/`·report 레이어의 **의견서 생성 템플릿 정본**. 참고 모델 리포트 예시(내부 학습용)와 달리 이건 **실제 공시 문구·면책·독립성 표현**까지 정본.

### ② 지식원천 RAG — 방법론·가정 선례 (최고 신뢰 코퍼스)
- 3-코퍼스 중 **지식원천**의 최상위 신뢰 레이어(공인 평가기관 공식 견해).
- 산업별·목적별 평가방법 선정 논리, WACC/영구성장률/할인율 범위, 비영업자산·이자부부채 분류 관행 → 가정 도출 시 인용.
- provenance: "영구성장률 1%는 [○○ 자산양수도 DCF 의견서] 관행에 부합".
- 참고보고서와 **분리·가중**: 평가기관 의견서 = 규범적 선례(높은 가중), 증권사 = 시장 관점.

### ③ 감사인 트랙 — 핵심 test material (⭐)
감사인 트랙은 *제공된 평가의견서*를 받아 검증하는 것이 목적. **이 실제 의견서들이 그 입력 샘플/테스트셋**:
```
OCR → auditor/ingest_opinion.py: 유의적 가정·방법·데이터 파싱
  → auditor/tests.py: FS·주석과 tie-out (매출성장률·WACC·영구성장률·비영업자산)
  → auditor/independent.py: 감사인 독립 가정으로 calc_core 재실행 → 차이 리포트
```
- 예: 의견서의 WACC·영구성장률·매출성장 가정을 추출 → 우리 calc_core로 독립 재계산 → 점/범위 추정치 비교.
- ISA 540(회계추정치 감사) 대응: 유의적 가정의 합리성·데이터 신뢰성·방법 적정성 테스트.

## 3. 파이프라인

```
외부평가의견서 PDF(스캔)
  → parsers/pdf.py + OCR (한국어)
  → 표/섹션 재구성 → 4종 검증(validators)
  → [평가자] rag 지식원천 코퍼스 (방법론·가정 선례)
  → [감사인] ingest_opinion → 유의적 가정 추출 → tie-out·독립추정
  → [양식]  report 템플릿 (공시 구조·면책 문구)
```

## 4. Reporting 양식 설계 — 정형문구 자동삽입 + 가변 슬롯

의견서는 **정형(boilerplate) + 가변(data-driven)**으로 분해 → 템플릿 엔진(Jinja류)으로 자동생성.

### 정형 문구 (템플릿 내장 상수, 자동삽입)
관례적으로 거의 동일하게 반복 → 준거기준 버전별로 상수 블록 관리:
- **준거기준**: 자본시장과금융투자업에관한법률·시행령, 외부평가업무 가이드라인(금감원), 감정평가 실무기준 등.
- **평가기관 독립성·적격성** 선언문.
- **평가의 한계 및 유의사항**: 추정의 불확실성, 미래정보 의존, 특정목적 한정.
- **이용제한·면책**: 본 의견서는 ○○ 목적에 한하여 이용, 제3자 배포 제한 등.

### 가변 슬롯 (calc_core·가정에서 치환)
| 슬롯 | 소스 |
|---|---|
| 대상회사·평가기준일·평가목적 | 프로젝트 메타 |
| 방법론 선정근거 | 대상 성격 → DCF±보조(§1 taxonomy 로직) |
| 주요가정(추정기간·매출·WACC·g) | Assumption + provenance |
| 평가결과(EV·지분가치·주당가치) | `calc_core` 결과 |
| 민감도표 | `dcf.run` sensitivity |
| 유사회사·WACC 빌드업 | `wacc` + peer |

### 구현 방향
```
report/
  templates/opinion_ko.jinja      # 정형 문구 + {{슬롯}}
  boilerplate/기준_v2024.md        # 준거기준·면책 상수(버전관리)
  render.py                        # calc_core 결과 + 가정 → 의견서 초안(docx/pdf/html)
```
> 정형 문구는 **버전 태깅**(법령 개정 반영). 가변 슬롯은 전부 provenance 부착 → 감사인 추적. 참고 모델 리포트 예시(내부 양식)와 외부평가의견서(공시 양식) 두 프로파일 지원.

## 5. 우선순위
- **P1 (감사인 트랙)**: 의견서 → 유의적 가정 추출 → 독립 재계산. 이 폴더가 감사인 트랙 개발의 실데이터.
- **P2 (양식)**: 정형문구+가변슬롯 템플릿(위 §4).
- **P3 (지식원천)**: 방법론 선례 RAG.

> 저작권: DART 공시 문서(공개)지만 3rd-party 저작물 → 로컬 처리만, 레포 미포함. 추출된 *방법론 패턴*(비식별)만 명세로 보존.
