# 모델링 워크플로우 기초 — 프로세스·역할·엑셀 규율

> 출처: 컨설팅 실무 교육 문서 2편(모델링 기초·모델링 엑셀 활용법). **워크플로우 흐름의
> 정본** — 우리 Skill 단계 설계·xlsx export 규율의 실무 근거.

## 1. 모델링의 정의와 구조

**과거 실적을 주요 driver 로 쪼개어 분석한 후, 각 driver 의 추정으로 미래 실적을 전망**:

```
과거 전체 ──Driver도출──▶ 과거 부분 ──Projection──▶ 미래 부분 ──Sum──▶ 미래 전체
```

분해(과거)→추정(부분)→합산(미래)의 3악장. 우리 계정분류(xDCF)→가정산정→DCF 파이프라인과
동형 — 계정분류가 'Driver 도출', 가정 산정이 'Projection', calc_core 가 'Sum'.

## 2. 모델 유형 3종
| 유형 | 용도 |
|---|---|
| **OP Model** | 인수 대상회사 향후 매출 추정 — deal valuation (우리 주 트랙) |
| **Pro-Forma Model** | 회사·사업의 예상 매출/수익성 — 마일스톤별 목표 세팅·관리 |
| **Market Model** | 대상 시장 사이즈 추이·성장 전망 (top-down 매출법의 기반) |

## 3. 모델의 목적과 구조 요건 3
목적: 미래값 추정 · **driver 별 영향도 파악** · 시간 흐름에 따른 재적용.
1. **정량(모델 결과)–정성(스토리라인) alignment** — 숫자와 서사가 어긋나면 안 됨
   (Brief·리포트와 모델의 정합; [[장표_작성법]]의 메시지 원칙과 동일 축).
2. **Driver 영향 isolation 구조** — 민감도가 driver 단위로 분리되게(우리 2-way 민감도·
   driver 토글 설계 근거).
3. **수정 시 변수값 변경 외 작업 최소화** — 구조 재수술 없이 input 만 바꿔 재계산
   (우리 xlsx 왕복 import 의 "고정 입력셀 맵" 철학).

## 4. 모델러 역할 5 + 업무 프로세스 8단계 ⭐
역할: ①과거 데이터 분석 ②추정 방법론 설계(추정 단위: 고객/제품/채널 × Top-down/Bottom-up)
③**Input 값 요청**(필요 정량·정성 input 정의 → RFI·인터뷰·질의자료) ④추정 ⑤설명·보고.

```
RFI 작성·송부 → 과거 데이터 분석 → 추정 방법론 도출 → Skeleton 구성
→ 과거실적 입력 → Projection → 장표 작성 → Follow-up
```

- **RFI 가 첫 단계**: 자료가 안 오면 아무것도 못 함 — "무엇이 필요한지"를 먼저 정의해
  요청(우리 assist/chat 의 "경영진 자료 필요" 요청 루프의 실무 원형).
- **Skeleton 을 과거실적 입력보다 먼저**: 구조(시트·행렬 골격)를 확정한 뒤 숫자를 채움 —
  방법론이 구조를 결정하지, 데이터가 구조를 끌고 가지 않는다.
- 장표 작성이 종착([[장표_작성법]]) + Follow-up(수정 재적용)까지가 한 사이클.

## 5. 태도 3원칙
**정확성**(key-in·함수 전 과정 무오류) · **Ownership**(문제는 가설이라도 만들어 소통) ·
**적시성**(sanity check·formatting 을 미리 해둬 버전 공유 요청에 즉시 대응).

## 6. 엑셀 규율 — 2대 축: Reader Friendliness × Zero Defect ⭐

### Reader Friendliness (가독성)
- **최종 산출물과 방법론을 먼저 구상하고 엑셀을 연다** — Key Questions:
  최종산출물 정의 → 추정단위 설정 → 단위별 추정방법론 → Proxy(계산용 데이터) 수집 방법론.
- **시트 구성 4종 + 단방향 참조 규율**:
  ```
  Assumption ← Summary ← Results ← Backdata     (참조는 뒤→앞 한 방향만)
  ```
  Backdata 참조는 Results 에서만, Results 참조는 Summary 에서만 — 가독성·수정용이성·
  무결성이 이 규율에서 나온다. (우리 xlsx export 시트 설계·의존그래프 검증의 정본 규칙.)
- **컬러코딩 정본**(문서 내 실제 모델 캡처): **Blue=직접 입력 hard 값 · Black=해당
  시트에서 계산된 값 · Green=여타 시트를 참조한 값**. 셀 색만 보고 "어디를 고치면
  되는지/어디서 왔는지"가 즉독 — xlsx export 시 이 3색 규약을 그대로 적용.
- **시트 탭 실례**(동 캡처): `Cover | Assumption | CON | <Results 시트들> | -> Mkt |
  Mkt | -> Mgmt.Plan | Mgmt. | -> RAWDATA | Raw` — Backdata 그룹에 `->` 접두 시트
  (원천→모델 형식 변환 브리지)를 두는 관행. 참조 화살표는 Backdata→Results 한 방향.
- **Leveling**: 주요 추정 driver 를 분리 배치하고 계산구조와 Proxy 를 적시 — 로직이
  눈에 보이게.

### Zero Defect (무결성)
- **Sanitizing & Cleansing**: 외부 수령 raw data 는 반드시 ①오류 검토(합계·분류 오류)
  ②재가공 시 **구분자 추가**(원본과 가공의 경계 표시) 후 사용 — 우리 validators 4종
  (숫자형·공백·합계·정합성)과 provenance 원칙의 실무 원형.
- **오류 가능성 낮은 작업방식**: 값이 0/없어도 동일 Set 반복 배치(구조 일관), 시트 간
  연도·행열 일치(교차 검증 용이), **hard number 는 최초 1곳만 입력하고 나머지는 참조
  (soft number)** — SSOT 원칙의 엑셀 판.
- **오류 발견 장치**: 시트 내외 교차 확인 · **일부 연도 값/비중/YoY 가 튀면 재검토** ·
  숫자로 안 보이면 그래프로 경향성 확인. (→ 우리 checks 의 YoY 급변 WARN 규칙 근거.)

### (참고) 함수·단축키
문서 후반은 엑셀 함수 레퍼런스(COUNT·SUMIF 계열/텍스트/날짜/VLOOKUP·INDEX·MATCH·
OFFSET)와 단축키(Ctrl+화살표, Ctrl+Shift+[ 참조 셀 추적, F5+Enter 복귀, Alt→E→S
선택 붙여넣기 V/T/F 등) — 일반 지식이라 상세 생략. 눈여겨볼 것: **Ctrl+Shift+[ (참조
추적)·F5+Enter(복귀)** 가 실무 검증 루틴(참조 사슬 걷기)의 기본기라는 점.
