# DCF 계정분류 체계 & 자동화 모델 아키텍처

> **밸류에이션 북 챕터.** 재무제표(PL/BS)를 DCF 평가모델로 변환할 때, 모든 계정을 **계정유형**과
> **분석방법**으로 분류하는 표준 체계와, 그 위에 세워지는 추정 파이프라인을 정리한다.
> 출처: 자동화 서비스 xDCF(xdcf.co) 유저 매뉴얼 + 샘플 모델. 실무 DCF의 계정 취급을 압축한 권위 자료.

---

## 1. 핵심 개념 — 계정을 "유형 × 방법"으로 분류

DCF 모델링의 첫 단계는 재무제표의 각 계정과목을 두 축으로 태깅하는 것이다:
- **계정유형(Account Type)**: 이 계정이 DCF 구조상 *어디로 흘러가는가* (매출·원가·운전자본·고정자산…).
- **분석방법(Analysis Method)**: 이 계정을 미래로 *어떻게 추정하는가* (성장률·비율·단가×수량…).

이 두 태그만 정해지면 나머지 모델(추정 PL/BS → FCF → DCF)은 결정론적으로 조립된다.

---

## 2. 계정유형(Account Type) Taxonomy

### 손익계산서(PL) — 4유형
| 코드 | 의미 | 설명 |
|---|---|---|
| **Sales** | 매출액 | 수익 라인 |
| **COGS** | 매출원가 | 매출 대응 원가 |
| **SGA** | 판매비와관리비 | 영업비용 |
| **NO** | 영업외손익 | 영업과 무관(이자수익 등) — FCF서 제외 |

### 재무상태표(BS) — 6유형
| 코드 | 의미 | DCF 취급 |
|---|---|---|
| **WC** | 운전자본 | 매출채권·재고·매입채무 → ΔWC 로 FCF 반영 |
| **FA** | 고정자산 | 유형·무형자산 → CAPEX·감가상각 |
| **NOA** | 비영업자산 | 금융상품·투자자산 → EV에 가산 |
| **IBD** | 이자부부채 | 차입금·사채 → 지분가치서 차감 |
| **OAL** | 기타영업자산·부채 | 위 외 영업 관련 |
| **EQU** | 자본항목 | 자기자본 |

> **핵심 원리**: BS 계정을 WC/FA/NOA/IBD로 가르는 것이 DCF 브리지(EV→지분가치)의 근간.
> 매입채무 같은 영업부채는 **WC**(운전자본)로, 차입금은 **IBD**(이자부부채)로 — 이 구분이
> [[deloitte_감사인검토_WACC방법론]]의 "이자부부채만 타인자본" 원칙과 직결.

### 분류가 모호한 실무 쟁점 (블로그 보강)
| 항목 | 쟁점 | 처리 |
|---|---|---|
| **현금** | "영업에 항상 필요한 최소수준인가" | 최소영업현금=WC 포함 가능, 잉여=NOA. 전액 NOA 처리도 관행 |
| **무역어음** | 회계상 차입금이나 본질이 무역(영업) | 영업 본질이면 **WC** 분류 가능(IBD 아님) |
| **이연법인세** | 세금효과 이중계상 위험 | CF에 반영된 세금과 중복 방지, 신중 처리 |
> 회계기준 재무제표를 **평가 목적에 맞게 조정**하는 과정 자체가 분류의 본질.

## 3. 분석방법(Analysis Method) Taxonomy

### Sales(매출) 추정방법 — 6종
| 방법 | 로직 |
|---|---|
| **매출성장률** | 전년 매출 ×(1+성장률). 성장률 소스: **GDP성장률(기본)** / CPI / Research / 자체분석 |
| **시장점유율** | 시장규모 × 점유율. 잔여시장 옵션 = 전년시장 ×(1+시장성장률) × 점유율 |
| **생산능력** | Capacity 기반 |
| **시장점유율 및 생산능력** | 두 제약 결합 |
| **매출성장률 및 생산능력** | 성장률 + capacity 상한 |
| **단가 × 판매량** | P × Q ([[모델링_실무_2강4강]]의 bottom-up과 동일) |

**매출성장률의 성장률 소스 (드롭다운)**:
`1: Research Analysis | 2: GDP Growth Rate(기본) | 3: CPI Growth Rate | 4: 자체분석`
→ 매크로(GDP/CPI)가 **Data 시트와 수식 연결**되어 자동 주입. 이것이 [[영구성장률_PGR_적합성]]의
"PGR ≤ GDP" 원칙을 명시기간 성장률에도 적용한 실무 구현.

### COGS·SGA(비용) 추정방법 — 4종
| 방법 | 로직 | 예시 계정 |
|---|---|---|
| **인건비** | 임금상승률(DAWA) 연동 | 노무비·급여·상여·퇴직급여·복리후생 |
| **변동비** | 매출 대비 비율 | 재료비·여비교통비 |
| **고정비** | 물가상승률(CPI) or 고정 | 임차료·보험료·통신비·수수료·광고선전 |
| **상각비** | FA 시트 감가상각 스케줄 연동 | 감가상각비·무형자산상각 |

> **비용을 4가지로 나누는 이유**: 각 비용의 **성장 드라이버가 다르다**. 인건비=임금상승률,
> 변동비=매출연동, 고정비=물가/고정, 상각비=자산스케줄. 뭉뚱그리면 마진 추정이 왜곡된다.

## 4. 모델 아키텍처 (자동생성 28시트 파이프라인)

```
[사용자 입력]  BI · WACC · PL · BS          (분홍색 셀만 채움)
     │
[조정 레이어]  PL_A/BS_A (실사조정) → PL_F/BS_F (조정반영 최종 재무제표)
     │
[외부 데이터]  Data (EIU 국가·연도별 물가/GDP/임금 → 분석시트에 수식연결)
     │
[항목 분석]    Sales·COGS·SGA·NO      (PL 계정유형별)
               WC·FA·NOA·IBD·OAL·EQU  (BS 계정유형별)
               TAX (영업이익 기준 법인세+지방세 한계세율)
     │
[추정 재무제표] Est_PL · Est_BS         (자동작성)
     │
[가치평가]     DCF → Report_DCF        (계산층 → 발표층)
               Report_Est_PL · Report_Est_BS
```

### 레이어 설계의 요점
- **입력 최소화**: 사용자는 분홍색 셀만. 헤더·수식은 자동. WACC는 약식이면 최종 WACC 한 칸만.
- **_A / _F 분리**: `_A`=실사조정 입력, `_F`=조정 반영 최종 → 모델은 `_F` 기준. 원본 불변 + 조정 추적.
- **Data 매크로 연동**: 물가·GDP·임금이 국가·연도별로 프리로드되어 driver에 자동 주입.
  추정 없는 연도는 전년 상승률 지속(회색음영).
- **Report_ 발표층 분리**: 계산시트(Est_·DCF)와 보고서시트(Report_)를 물리 분리 =
  [[외부평가의견서_활용]] §4 정형문구+슬롯의 구현체.

## 5. 정교한 실무 처리

### Stub Period (평가기준월 ≠ 결산월)
평가기준월 6월, 결산월 12월 → **이전/이후 개월 분석** 필요:
- 이후 개월 매출 = 이전 개월 매출을 개월수로 안분 (동일 매출 지속 가정), 또는
- 전년대비 성장률 적용해 금년 매출 산출 후 이전 개월분 차감.
- 시장점유율: 이전/이후 개월 시장규모 = 전년시장 ×(1+시장성장률)/12 × 개월수 × 점유율.
> 우리 `mid_year_periods`(0.5,1.5…)보다 정교한 **부분기(stub) 안분** — 개선 후보.

### 세율 자동 (한계세율)
추정 영업이익에 따라 **한계세율(법인세+지방세)** 자동 계산 → WACC·FCF에 반영.
= 우리 `corporate_tax(EBIT)` 구간세율 자동화(개선 A)와 동일 사상.

## 6. ⭐ LLM 활용 — 경쟁사의 현재 수준 & 우리 기회

### xDCF의 LLM 사용 (매뉴얼 명시)
> "계정유형 또는 분석방법이 **공란인 경우 ChatGPT가 계정과목과 숫자를 검토하여 자동으로 채워**주므로
> 공란으로 두셔도 괜찮습니다. (단, ChatGPT가 Sales의 분석방법을 가장 일반적인 '매출성장률'로
> 분류하는 경우가 많으므로 Sales는 직접 기재 추천)"

→ 경쟁사의 LLM 활용 = **계정 → (계정유형, 분석방법) 분류** 딱 한 지점. 그마저 Sales 오분류 한계 인정.

### 우리 차별화 (밸류에이션 북 기반 LLM)
| 층위 | xDCF (ChatGPT 단순분류) | 우리 (Book RAG + 결정론 엔진) |
|---|---|---|
| 계정 분류 | ✅ (Sales 약점) | ✅ + 근거 있는 분류(이 taxonomy를 RAG로) |
| 방법 **판단** | ❌ 기본값 의존 | ✅ 산업·계정 특성 근거로 방법 추천([[모델링_실무_2강4강]] 구분실익) |
| 가정 **타당성** | ❌ | ✅ checks.py(PGR≤GDP·TV비중·재투자·β/ERP) |
| 재현·출처 | ❌ | ✅ 골든재현 + value-level provenance |
| 감사 대응 | ❌ | ✅ tie-out + 감사인 트랙 |

> **포지셔닝**: xDCF = "재무제표 넣으면 엑셀 뱉는" 자동화. 우리 = **"왜 이렇게 평가했는지 설명·검증하는"
> LLM 밸류에이션 어드바이저**. 이 문서(계정 taxonomy)가 그 LLM의 분류·추천 근거 코퍼스.

## 7. 우리 플랫폼 반영 (로드맵)
- **[HIGH] 계정 taxonomy 스키마**: `AccountType`(Sales/COGS/SGA/NO, WC/FA/NOA/IBD/OAL/EQU) +
  `AnalysisMethod` enum. 인제스트(DART/파서) 값에 태그 → 자동 모델 조립.
- **[HIGH] Data 매크로 레이어** `macro.py`: 국가·연도별 GDP/CPI/임금 테이블 → driver·PGR 연동.
- **[HIGH] LLM 분류기**: 계정→(유형,방법) 분류를 이 Book으로 RAG. Sales는 특별 취급(경쟁사 약점 공략).
- **[MED] 조정 레이어** `_A/_F`: 실사조정 입력 + 원본 불변 병합.
- **[MED] Stub period**: 평가기준월≠결산월 부분기 안분.
- **[MED] 브리지 항목화**: NOA/IBD를 항목 리스트로(현재 스칼라).

## 부록 A. Report_DCF 발표 포맷 (보고서 슬롯 스키마)
발표층(Report_DCF)의 표준 라인 순서 — 우리 report 템플릿 슬롯으로 채택:
```
매출액 → 매출액증가율 → 매출원가 → 매출원가율 → 매출총이익 → 매출총이익률
→ 판매비와관리비 → 판관비율 → 영업이익 → 영업이익률 → 법인세비용 → 세후영업이익
→ CAPEX → 상각비 → 순운전자본변동 → 잉여현금흐름(FCF) → 현가계수 → 할인된FCF
→ 영업가치 → 비영업자산 → 기업가치 → 이자부부채 → 주식가치
+ 민감도(WACC × 영구성장률 그리드)
+ 비영업자산 내역(보통예금·단기/장기금융상품) · 이자부부채 내역(단기차입금·전환사채)
```
- **T.V.(터미널) 열** 별도, 영구성장률 g = **1%**(한국 보수 관행, [[영구성장률_PGR_적합성]] 일치).
- 각 라인에 **비율(율)** 동반 표기(매출원가율·판관비율·영업이익률) → 감사·해석 편의.

## 부록 B. 서비스 운영 팩트 (경쟁 정보)
- **플로우**: FS 업로드 → 약 15분 후 완성 DCF 엑셀(`원본명_xDCF.xlsx`) 이메일 수신. 무설치.
- **입력**: 양식 다운로드 → E-mail 입력 → 파일 업로드 → Send. 데이터 **7일 내 폐기**.
- **모델 특징**: 전 수식 연결(수정 자유), 최장 **30년** 추정, 원/백만원 단위 전환, 모든 결산월 지원.
- **계정과목 5단계**: 대/중/소/세/세세분류 (회계상 계정과 불일치 허용, 최종 분석계정만 남김).
- WACC provenance: Rf(Bloomberg)·MRP(**KICPA 8%**)·Kd(**금융투자협회** 신용등급)·"임의 할인율 가능"
  → 우리 `beta_source/erp_source` provenance가 업계 관행임을 확증.
