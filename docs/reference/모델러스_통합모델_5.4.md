### 1.1 참조 그래프 (참조 과정 = 뒤→앞 단방향)

```
rGDP / rInflation / rWage ─┐
rFS / rSegment ────────────┼─→ EBIT ─→ Model ─┬─→ DCF ─────┐
rTrading ──────────────────┘      ↑           └─→ Trading ─┼─→ Summary
                                  │                        │
                            Scenario ←──────────────────────┘
                         (드라이버 주입 ↑ / 결과 표시 ↓)
```

**핵심 규약 — `r` 접두사 원자료 격리**: 붙여넣은 외부자료는 전부 `r*` 시트에만 존재하고
**절대 수정하지 않는다**. 모델 시트는 오직 참조만 한다. `RAW >>` 라는 빈 구분 시트로
탭 영역을 물리적으로 갈라놓는다.

**⚠️ Scenario 의 양방향성 (시트순환 vs 셀 DAG)**:
- 과거 실적: `Scenario!I15 = EBIT!I37` (EBIT → Scenario)
- 추정 드라이버: `EBIT!O37 = Scenario!O15` (Scenario → EBIT)

**시트 레벨로는 순환이지만 셀 레벨로는 DAG** 다(과거열/추정열이 서로 다른 셀). 우리 스킬의
`참조 단방향(뒤→앞, 순환 금지)` 규약은 **시트 단위로 읽으면 이 정당한 패턴을 금지**하게 된다
→ 규약을 **셀 단위 DAG** 로 정밀화할 것 (§5 반영점 R7).

### 1.2 시트 헤더 규약 (전 시트 공통, 5–7행)

```
I5:'Circuit Switch :'  L5:'ON'      | O5:'Hardcode'    Q5:'Caution'
I6:'Scenario :'        L6:'BASE'    | O6:'Calculation' Q6:'Assumptions'
I7:'Target Price :'    L7:144,000   | O7:'Reference'   Q7:'Notes'
```

**모든 시트 상단에 전역 상태(순환스위치·선택 시나리오·현재 타깃가격)를 노출**한다.
어느 시트를 열든 "지금 이 모델이 어떤 상태인지"가 보인다. 색상 범례도 시트마다 반복.
색상은 3색(Hardcode/Calculation/Reference) + 3의미(Caution/Assumptions/Notes) = **6분류**로,
우리 3색(Blue/Black/Green)+yellow 보다 한 단계 세분.

## 2. 모듈별 로직 (수식 정본)

표기: 열 `H~N` = 과거 2016–2022A, `O~S` = 명시추정 2023–2027E, `T~X` = 페이드 2028–2032E.

### 2.1 `EBIT` — 매출·원가·판관비 빌드업

#### (a) 매출 = P × Q 트리 (2계층)

```
O15 총매출 = O16 + O23 + O30                    (보톡스 + 필러 + 기타)
O16 보톡스 = O17 + O20                          (내수 + 수출)
O17 보톡스 내수 = O18 × O19 / 10^6              (판매량 vials K × ASP KRW)
O18 판매량   = N18 × (1 + O37)                  ← O37 = Scenario!O15
O19 ASP      = N19 × (1 + O38)                  ← O38 = Scenario!O16
```

**제품 × 지역 2축으로 쪼갠 뒤 각 축을 수량·단가로 다시 쪼갠다.** 성장률은 전부
Scenario 시트에서 주입 → 시나리오 스위치 하나로 매출트리 전체가 움직인다.
우리 W2.5(FS_Disagg) → W4(Fcst_Rev) 설계와 동형 — **실측 검증됨**.

#### (b) 인건비 bottom-up (⭐ 우리 미보유 패턴)

```
O102 총인건비   = O104 × O122
O104 총인원     = SUM(O105:O110)        (제조/QC·영업·구매·전략·재무IR·IT인사 6직군)
                  각 직군 = 드라이버당 인원 (113~120행)
O122 1인건비    = O123 × O124 × O125 / 10^9
                  O123 연근무일 250.7 · O124 일근무시간 9 · O125 시급
O125 시급       = N125 × (1 + O126)
O126 시급성장률 = AVERAGE(rWage!H3:L3)/100 = 3.54%   ← 거시 원자료 앵커링 ⭐
```

**인건비를 "인원 × 시급 × 시간"으로 완전 분해하고, 임금상승률을 거시 통계 5년 평균에
앵커링**한다. 가정이 하드코드가 아니라 **출처 있는 파생값**.

#### (c) 원가·D&A 배분 레이어 (⭐ 우리 미보유)

```
[인건비 배분]  O130 총액 = O102
               O132 → 판관비 = O130 × O133(%판관비)
               O131 → 매출원가 = O130 − O132        (잔차로 배분, 합보존)
[감가상각 배분] O137 총액 = Model!O67
               O139 → 판관비 = O137 × O140
               O138 → 매출원가 = O137 − O139
```

**성격별 비용(인건비·감가상각)을 먼저 총액으로 추정한 뒤 COGS/SG&A 로 배분**한다.
배분은 항상 `한쪽 = 총액 × %`, `다른쪽 = 총액 − 앞쪽` 의 **잔차 방식** → 합보존이 수식으로 강제됨.

### 2.2 `Model` — 3표 연결 + 6 스케줄

#### (a) 손익계산서

```
O15 매출 = EBIT!O15        O16 COGS = EBIT!O53      O19 판관비 = EBIT!O80
O20 EBIT = O17 − O19
O22 이자수익 = IF($L$5="ON", O166, 0)      ← 순환 스위치 ⭐
O23 이자비용 = O149                          ← 부채 스케줄
O25 EBT = O20 + O22 − O23 + O24
O26 법인세 = O25 × O27       (O27 = 24.2% 하드코드)

```

#### (b) CHECK 행 (라이브 정합 검증) ⭐

```
O61 [대차]   = IF(O33 = O45+O55, "TRUE", O33−O45−O55)     자산 = 부채 + 자본
O89 [현금연결] = IF(O35−N35 = O87, "TRUE", O35−N35−O87)   현금증감 = CF 순증감
```

**불일치 시 TRUE/FALSE 가 아니라 *잔차 금액* 을 표시** — 바로 원인 추적이 가능하다.
단, **정확일치 비교라 부동소수 노이즈에 취약**: 실제로 `I89 = -7.105e-14`,
`J89 = 6.217e-15` 로 **2개 연도가 TRUE 를 못 띄운다**(§4 결함 D1).

#### (c) 운전자본 스케줄 — 회전기일 구동

```
O100 매출채권 = O93(매출) × O110(DSO) / 365
O101 재고자산 = O94(COGS) × O111(DIO) / 365
O105 매입채무 = O94(COGS) × O113(DPO) / 365
O96  순운전자본 = O99(영업CA) − O104(영업CL)
O97  ΔNWC      = O96 − N96

[드라이버 = 과거 평균]
O110 DSO = AVERAGE(L110:N110)    ← 3년 평균
O111 DIO = AVERAGE(J111:N111)    ← 5년 평균
O113 DPO = AVERAGE(J113:N113)    ← 5년 평균
```

**⚠️ lookback 창이 항목마다 다르다(3년 vs 5년)** — 명시적 판단이지만 근거가 시트에 없다.
우리 provenance 대장은 `가정명|값|출처|근거` 를 요구하므로 **lookback 창과 그 사유를
필수 필드로** 승격할 근거 (§5 반영점 R9).

#### (d) 유형자산 롤포워드

```
O120 기초 = N125(전기 기말)
O121 CAPEX = O118(매출) × O122(%)        ← 매출 연동
O123 감가상각 = O120(기초) × O124(%)      ← 기초잔액 연동 ⭐
O125 기말 = O120 + O121 − O123

**감가상각은 기말이 아니라 *기초* 잔액 기준** — 당기 취득자산에 만기 상각을 물리지 않는
보수적·표준 처리. 무형자산도 동일 구조(127–132행).

```

O147 평균잔액     = AVERAGE(N146, O146)      ← 기초·기말 평균 ⭐

#### (f) 이자수익 스케줄 — **순환의 근원**

```
O163 이자부자산 기말 = O35(현금) + O36(단기금융자산)
O164 평균잔액       = AVERAGE(N163, O163)
O166 이자수익       = O164 × O165
```

**순환 고리**: `이자수익 → EBT → 순이익 → CF → 현금(O35) → 이자부자산 → 평균잔액 → 이자수익`.

이를 `Model!L5` 의 **Circuit Switch** 로 통제한다:
`O22 = IF($L$5="ON", O166, 0)`. OFF 로 내리면 고리가 끊겨 `#REF!`/발산 없이
모델을 안전하게 열고 디버깅할 수 있다. **완성본은 `ON`**(반복계산 활성 전제).

> **우리에게 시사하는 바**: FCFF 기반 DCF 는 **무차입 기준**이라 이자수익·이자비용이
> 원천적으로 불필요하다 → 우리 DCF 스파인에 순환은 영원히 불필요하다. 순환은 **3표를
> 완결(BS 대차·CF 연결)하려는 목적에서만** 발생한다. 우리가 3표 완전연결로 확장할 때에만
> 이 스위치 패턴이 필요하다 (§6 결정표: 조건부 채택).

### 2.3 `DCF` — 3단 구조 (⭐ 최대 학습 포인트)

#### (a) 기간 구조 = 명시 5년 + 페이드 5년 + Gordon

| 단계 | 연도 | 열 | 산출 방식 |
|---|---|---|---|
| **1. 명시추정** | 2023–2027E | O~S | `Model` 시트 완전연동 (드라이버 기반 3표) |
| **2. 페이드(수렴)** | 2028–2032E | T~X | 단순 비율고정 성장 |
| **3. 영구** | 2033– | — | Gordon |

#### (b) 페이드 구간 로직 — 비율 동결 + 단일 성장률

```
T14 매출   = S14 × (1 + T15)
T15 성장률 = $F$30 (전 페이드 연도 동일)
             F30 = AVERAGE(S15, F33) = AVERAGE(13.101%, 1.62%) = 7.361%   ⭐
                   ↑ 마지막 명시연도 성장률과 영구성장률의 중간값

T17 OPM      = $F$31 = S17 = 42.206%     ← 마지막 명시연도 고정
T19 세금/EBIT = $F$32 = S19 = 25.071%     ← 마지막 명시연도 고정
T16 EBIT = T14 × T17        T18 세금 = T16 × T19       T20 NOPLAT = T16 − T18

T21 감가상각 = S21 × (1 + T$15)     ┐
T22 무형상각 = S22 × (1 + T$15)     │ 전부 매출과 같은 속도로 성장
T23 CAPEX-유형 = S23 × (1 + T$15)   │ → 매출대비 비율이 동결됨
T24 CAPEX-무형 = S24 × (1 + T$15)   │
T25 ΔNWC      = S25 × (1 + T$15)    ┘
```

**페이드 구간의 본질**: 마지막 명시연도의 **모든 비율(마진·세율·CAPEX/매출·D&A/매출·ΔWC/매출)을
동결**하고, 성장률만 명시말기와 영구의 중간값으로 낮춰 5년간 유지한다. 결과적으로
**자기정합적 정상상태(steady state)** 가 만들어진다 — 재투자(CAPEX 117.8 ≫ D&A 52.0)가
계속 살아 있으므로 우리 `terminal_reinvestment` 검사가 요구하는 재투자 반영이
**구조적으로 충족**된다.

#### (c) FCFF · 할인 · 터미널

```
O26 FCFF = O20(NOPLAT) + O21(D) + O22(A) − O23(CAPEX유형) − O24(CAPEX무형) − O25(ΔNWC)
O10 할인계수 = 1/(1+$F$34)^O11
O11 기간     = N11 + 1,  N11 = −0.5  →  0.5, 1.5, 2.5 … 9.5      ← mid-year ⭐
O27 PV(FCFF) = O26 × O10

F40 터미널가치 = (X26 × (1+F33)) / (F34 − F33)        Gordon, 최종연도 FCFF 기준
F39 PV(TV)    = F40 × X10                              ← t = 9.5 (mid-year 계수 재사용) ⭐
F38 PV(명시+페이드) = SUM(O27:X27)
F37 EV = F38 + F39
```

**⚠️ 터미널 할인기간 t = 9.5 선택**: TV 는 2032년 *말* 시점 가치이므로 `t=10` 도 정당하다.
모델러스는 **최종 명시연도 현금흐름과 동일한 mid-year 계수(t=9.5)를 재사용**했다 —
영구 스트림도 mid-year 로 도래한다고 보는 해석. 두 관행 모두 통용되나 **반드시 명시 선언**해야 한다.
우리 엔진은 `terminal_discount_period` 로 이미 노출 중 ✅.

> **영향 정량**: `t=10` 으로 바꾸면 PV(TV) 786.67 → 750.06, EV 1,360.8 → 1,324.2,
> 주당 144,000 → **141,000 (−2.1%)**. 무시할 수 없는 크기 → 선언 강제 근거.

### 2.4 `Trading` — 유사회사 배수

#### (a) 원자료 조회 = 2차원 INDEX/MATCH

```
S14 = INDEX(rTrading!$A$1:$Y$10,
            MATCH(Trading!$N14, rTrading!$A$1:$A$10, 0),    ← 행: 티커
            MATCH(Trading!S$9,  rTrading!$A$1:$Y$1,  0))    ← 열: 필드명
```

9행에 필드명(`PRICE`·`MKT_CAP`·`EBITDA_LTM`…)을 숨겨두고 **행=티커·열=필드명 이중 MATCH**.
원자료 열 순서가 바뀌어도 깨지지 않는다. 직접 셀참조 대비 압도적으로 견고.

#### (b) EV 브리지 (peer 공통)

```
V14 EV = U14(시가총액) + X14(부채) + Y14(우선주) + Z14(비지배지분) − W14(현금)
```

**우선주·비지배지분까지 포함**한 정식 브리지.

#### (c) 배수 + NM/NA 가드

```
E14 EV/Sales = IF(ISERROR($V14/AE14), "NA",
                  IF($V14/AE14 < 0, "NM", $V14/AE14))
```

- 분모 0/결측 → `"NA"` (ISERROR)
- 음수 배수(적자) → `"NM"` (not meaningful)
- Excel `MEDIAN`/`AVERAGE` 는 **텍스트를 자동 제외** → 통계가 자연히 유효값만 사용

실제로 Humedix 는 FTM 예상치가 전부 0 → FTM 4개 배수가 모두 `NA` → FTM 통계는 n=4 로 계산됨.

#### (d) 배수 적용 — EV배수 vs 지분배수 **비대칭** ⭐

```
[EV 배수 경로]  E34 EV = E24(평균배수) × E29(대상 Sales)
                E36 지분 = E34 − E35(순차입)
                E38 주당 = ROUND(E36 / E37, −2)

[지분 배수 경로] H38 주당 = ROUND(H24(평균 P/E) × H29(대상 EPS), −2)   ← 직접 주당
                H36 지분 = H38 × H37
                H34 EV   = H36 + H35                                    ← 역산
```

**EV배수는 EV→차감→지분 순방향, 지분배수(P/E)는 지분/주당 직접 산출 후 EV 역산.**
분자·분모 일관성(Apple-to-Apple)의 교과서적 구현.

### 2.5 `Scenario` — CHOOSE 단일선택 스위치

```
E13 선택        = "BASE CASE"  (문자열 입력)
G13 인덱스      = IF(E13="BULL CASE",1, IF(E13="BASE CASE",2, 3))
O15 드라이버    = CHOOSE($G$13, O16, O17, O18)      ← Bull / Base / Bear

O17 Base = AVERAGE(K15:N15)      ← 과거 4년 평균 (평균회귀) ⭐
O16 Bull = O17 + 5%              ← "5%pts Added from Base Case" (V16 메모)
AB13 결과 = DCF!F44               ← 선택 즉시 타깃가격 표시
```

**패러다임**: 한 번에 **하나의 케이스만 살아있다**(단일선택 스위치).
우리 `scenario.py` 는 **확률가중 SUMPRODUCT**(기대값 혼합) — 서로 다른 패러다임이며 둘 다 정당하다.
- 스위치 = "약세 시나리오를 보여줘" 서사·발표용
- 가중 = 기대값 산출용

**Base = 과거 N년 평균**은 방어 가능한 기본 드라이버 규칙(평균회귀). Bull/Bear 는
**절대 %p 가감** 방식이고 그 폭을 메모열(V)에 기록한다.

## 4. 참조 모델의 결함 — **복제 금지 목록** ⚠️

## 5. 우리 로직 스킬 반영점 (우선순위)

### P1 — 엔진 구조 갭 (`calc_core` 변경 필요)

#### R1. 페이드(수렴) 스테이지 도입 ⭐ **최대 반영점**
**현황**: 우리 엔진은 `명시기간 + Gordon` **2단**. `dcf.py` 는 `terminal_ebit = ebit[-1]×(1+g)` 로
마지막 명시연도에서 **영구성장률로 즉시 점프**한다.
**문제**: 명시말기 13.1% 성장 → 영구 1.62% 로의 급단절. 이 불연속이 TV 를 왜곡하고,
명시기간이 짧을수록 TV 비중이 치솟아 우리 `TV_WEIGHT_WARN` 이 상시 발화한다.
**제안**:
```python
# models.py — DcfSpineInput 확장
fade_years: int | None = None          # 페이드 연수 (예: 5)
fade_growth: float | None = None       # None → AVERAGE(마지막 명시성장률, terminal_growth)
# 페이드 구간 규칙(모델러스 실증):
#   성장률  = fade_growth 고정
#   OPM·세율·CAPEX/매출·D&A/매출·ΔWC/매출 = 마지막 명시연도 비율 동결
```
**부수효과(중요)**: 페이드 구간은 CAPEX>D&A 를 유지하므로 **재투자가 구조적으로 모델링된다**
→ `check_terminal_growth` 의 `reinvestment_modeled` 를 페이드 존재 시 True 로 승격 가능.
현재는 `terminal_wc_ratio`/`terminal_reinvestment_rate`/`terminal_fcff_override` 3개만 인정.
**실증 근거**: 페이드 적용 시 TV 비중 57.8% (게이트 통과).

#### R2. PGR 거시 앵커링 + provenance 검사
**현황**: `check_terminal_growth` 는 PGR ≤ GDP 상한만 본다. **PGR 이 어디서 왔는지는 안 묻는다.**
**제안**:
- `macro_client` 에 `suggest_pgr_from_inflation(years=10) -> (value, provenance)` 추가
  (실증: 10년 물가 평균 = 1.62%, 한국 관행 0~1% 대비 합리적 상단)
- `checks.py` 에 `check_pgr_provenance(pgr, source)` 신설 — 출처 없는 PGR 은 WARN
- 임금성장률도 동일(`rWage` 5년 평균 3.54%) → `Fcst_Cost` 인건비 드라이버로
**의의**: 우리는 이미 `macro_client`(거시+vintage 이중가드)를 **보유**하고 있다. 데이터가 아니라 **배선**이 없다.

#### R3. 지분브리지 SSOT + 교차방법 일관성 검사 ⭐
**현황**: DCF 브리지(`net_debt`·`non_operating_assets`·`non_controlling_interest`)와
상대가치 브리지가 **독립적으로 입력**된다. 서로 달라도 아무도 안 잡는다.
**제안**: `checks.py` 에 신설
```python
def check_bridge_consistency(dcf_bridge, relative_bridge, *, tol=0.01) -> Finding:
    """DCF·상대가치가 같은 대상의 지분브리지를 쓰는지 검사.
    항목별(현금·단기금융자산·이자부부채·NCI·우선주) 대조 → 불일치 시 WARN + 델타 표면화.
    근거: 모델러스 5.4 D3 — 같은 워크북에서 순현금 426B vs 순부채 27B (지분가치 25% 차이)."""
```
**부가**: `account_dictionary.md` 에 **이자부자산 = 현금및현금성자산 + 단기금융자산** 을
명문 매핑으로 승격(vendor `CASH_LTM` 은 단기금융자산 제외 — 이 함정이 D3 의 원인).

### P2 — 스킬 템플릿·규약 (`SKILL.md` / `template_conventions.md`)

#### R4. 인건비 bottom-up + 비용배분 레이어 → `Fcst_Cost`
현재 `Fcst_Cost` 는 `영업이익 = 매출 − 원가 − 판관비` 수준. 추가할 살아있는 수식:
```
총인건비 = Σ(직군별 인원) × (연근무일 × 일근무시간 × 시급)
시급     = 전기 × (1 + 임금상승률)        ← Macro 시트 참조
[배분]   판관비분 = 총액 × %  /  원가분 = 총액 − 판관비분   (잔차 = 합보존 강제)
```
감가상각도 동일 배분 구조. `scaffold.py --stage W4` 뼈대에 반영.

#### R5. `Macro` 시트 신설 (W1 또는 W5)
`rGDP`/`rInflation`/`rWage` 대응. `macro_client` 산출을 시트로 고정하고
**PGR·임금상승률·GDP 상한이 전부 이 시트를 Green 참조**하게 한다. 가정의 출처가 시트로 추적된다.

#### R6. CHECK 행 라이브 규약 (**허용오차 필수**)
`Model` 계열 시트 하단에 상시 노출:
```
[대차]     =IF(ABS(자산 − 부채 − 자본) < 0.001, "TRUE", 자산−부채−자본)
[현금연결] =IF(ABS(Δ현금 − CF순증감) < 0.001, "TRUE", Δ현금−CF순증감)
```
**불일치 시 잔차 금액 표시**(TRUE/FALSE 아님) — 원인 추적용. 정확일치 금지(D1).

#### R7. 참조 단방향 규약을 **셀 단위 DAG** 로 정밀화
현행 `참조 단방향(뒤→앞, 순환 금지)` 은 시트 단위로 읽히면 Scenario↔EBIT 같은
**정당한 패턴을 오탐 금지**한다. 개정 문구:
> 참조는 **셀 단위로 비순환(DAG)** 이어야 한다. 시트 A·B 가 서로를 참조해도
> 참조되는 셀 집합이 분리(과거열/추정열)되면 허용한다. **셀 단위 순환은 금지** —
> 단, 3표 완결 목적의 이자 순환은 §R14 스위치 규약을 따른다.

#### R8. 가시 상태 헤더 (전 시트 5–7행)
`Circuit / Scenario / Target Price` + 색상범례를 모든 시트 상단에.
현재 `_VS_STATE` 는 **숨김 시트**라 사람이 상태를 못 본다 — 보완재.

#### R9. 원자료 격리 규약 `r*` + `RAW >>` 구분자
붙여넣은 외부자료는 `r` 접두사 시트에만, **무수정 원칙**. 우리 `FS_Hist`(Raw/Normalized)를
전 자료유형(peer·거시·세그먼트)으로 일반화.

#### R10. Peer 시트 원자료 조회 = 2차원 INDEX/MATCH
직접 셀참조 대신 `INDEX(raw, MATCH(티커,행), MATCH(필드명,열))`. 원자료 열 순서 변경에 견고.

### P3 — 판단 규율 (게이트·provenance)

#### R11. peer 자기제외 게이트 ⭐
`peer.py` 퍼널에 추가: **대상회사 티커가 peer 목록에 있으면 FAIL**(제외 후 재계산).
실증 영향 +7.9% (D4).

#### R12. 회전기일 드라이버 — lookback 창 + 사유 필수
`AVERAGE(과거 N년)` 은 좋은 기본값이나 **N 이 항목마다 다르면(실측 DSO 3년 / DIO·DPO 5년)
그 자체가 판단**이다. provenance 대장에 `lookback_years` + `사유` 필수 필드 추가.
(예: "2020 코로나 재고 이상치 제외 위해 DSO 만 3년")

#### R13. 시나리오 스위치 패러다임 병행
`scenario.py --switch --emit-cells` 추가 — `CHOOSE(선택인덱스, Bull, Base, Bear)` 방식.
현행 가중 SUMPRODUCT 와 **병행**(대체 아님).
- Base 기본규칙 = **과거 N년 평균**(평균회귀), Bull/Bear = **절대 %p 가감 + 메모열에 폭 기록**

#### R14. 순환 스위치 규약 (3표 확장 시 조건부)
FCFF DCF 는 무차입 기준 → **순환 불필요**. 3표 완전연결로 확장할 때만:
```
이자수익 = IF($순환스위치 = "ON", 스케줄, 0)
```
스위치 셀을 `_VS_STATE` 와 가시 헤더 양쪽에 노출. **DCF 스파인에는 영원히 도입 금지.**

#### R15. 터미널 할인기간 명시 선언 강제
`terminal_discount_period` 를 **선택이 아닌 필수 선언**으로. 미선언 시 WARN.
실증 영향 t=9.5 vs t=10 → 주당 **−2.1%**.

#### R16. 출력 반올림 규약
`ROUND(주당, −3)`(DCF, 천원) / `ROUND(주당, −2)`(Trading, 백원).
**허위정밀(spurious precision) 금지** — `lint_report.py` 표현 가드에 규칙 추가 검토.

## 6.5 P1 구현 결과 (2026-07-20)

세 반영점을 엔진에 이식하고 **원본을 독립 재현**해 검증했다.

| 반영점 | 구현 | 검증 |
|---|---|---|
| **R1 페이드** | `DcfSpineInput.fade_years/fade_growth` + `dcf._expand_fade` | 골든 7건 |
| **R1′ 터미널 컨벤션** | `terminal_from_last_fcff` (신규 발견 — 아래) | 골든 포함 |
| **R2 PGR 앵커링** | `macro_client.suggest_pgr_from_inflation` + `checks.check_pgr_provenance` | 7건 |
| **R3 브리지 SSOT** | `checks.check_bridge_consistency` | 4건 |

**구현 설계 — 페이드 = 계산분기가 아니라 *입력 확장***: `_expand_fade(inp, g)` 가 명시
시계열 뒤에 페이드 연도를 이어붙인 확장 입력을 만들고, 그 아래 할인·터미널·브리지·
민감도 로직은 **전부 무수정 재사용**된다. 하류 게이트(tv_weight·projection_smoothness·
working_capital_burn)도 페이드 포함 시계열을 자동 검사한다.
전 라인아이템을 동일 성장률로 성장시키는 것이 **"모든 비율 동결"과 수학적 동치**
(EBIT = 매출(1+g)×동결OPM = EBIT×(1+g), 모델러스 `T16 = T14×T17` 와 일치)라
구현이 한 줄로 떨어진다. `fade_years=None` 이면 입력을 그대로 반환 → **기존 2단 동작
완전 보존**(비올·클래시스 골든 불변).

**페이드 성장률은 `g` 의 함수**(`AVERAGE(마지막 명시 성장률, g)`)이므로 확장은 반드시
`_compute` **내부**에서 일어난다 — 민감도에서 g 축이 움직이면 페이드도 함께 움직여야
시나리오가 정합적이다.

### ⭐ 구현 중 발견 — 터미널 컨벤션 갈래 (문서 초안에 없던 항목)

페이드·할인·최종연도 FCFF 는 전부 일치하는데 **터미널만 어긋났다.** 원인:

| | 터미널 FCFF 산출 | 2032 기준값 |
|---|---|---|
| 우리 엔진(기존) | `NOPLAT_T` 재구축 (D&A=CAPEX, ΔWC=0) | 232.4 |
| 모델러스 | **마지막 FCFF × (1+g)** | 160.4 |

**1.45배** 차이가 그대로 TV 갭이 됐다. 우리 기본값은 재투자를 0 으로 두므로 g>0 에서
FCFF 과대(F1 경고 대상)이고, 모델러스는 마지막 해의 **실제 재투자 강도(CAPEX≫D&A,
ΔWC)를 영구 승계**한다. 둘 다 근사이나 **페이드와 함께 쓸 때는 후자가 더 정합적**이다 —
페이드 최종연도는 이미 비율이 동결된 정상상태라 그 FCFF 를 성장시키는 것이 자연스럽다.
→ `terminal_from_last_fcff` 플래그 신설. 우선순위:
`fcff_override > terminal_from_last_fcff > reinvestment_rate > (D&A=CAPEX − WC)`.

**`audit_dcf` 의 `reinvestment_modeled` 처리(정직성 주의)**: `terminal_from_last_fcff`
는 재투자 반영으로 **인정**하되, **`fade_years` 단독은 인정하지 않는다**. 페이드는 명시
구간의 현실성을 높이고 TV 비중을 낮출 뿐, 터미널 FCFF 자체는 여전히 `NOPLAT_T` 로
재구축되기 때문 — 페이드만으로 F1 을 PASS 시키면 거짓 안심이 된다.

### 실측 대조 (동일 입력, 페이드 유무)

| | 주당가치 | EV | TV 비중 | 게이트 |
|---|---|---|---|---|
| 페이드 5년 + 마지막FCFF 승계 | **144,000원** | 1,360.8B | **57.8%** | PASS |
| 페이드 없음(기존 2단) | 157,000원 | 1,519.8B | **84.6%** | ⚠ tv_weight |

**페이드를 빼면 같은 가정으로 9% 과대평가**되고 TV 비중이 게이트를 넘는다.
→ **TV 비중 경고가 뜨면 PGR·WACC 를 만지기 전에 페이드 구간부터 검토**하는 것이 정석.

### P3 추가 구현 (R11·R15)

**R11 peer 자기제외** — `select_peers(target_ticker=...)` 에 **Step0** 신설. 티커는
`normalize_ticker` 로 정규화해 `A145020`(FnGuide) ↔ `145020`(KRX·DART) 표기 차이로
게이트가 뚫리지 않게 했다. 자기제외된 대상은 Step2 판정 대상에서도 자동으로 빠진다
(판정 누락 `ValueError` 오발). 감사 마크다운에 탈락 사유가 그대로 남는다:
`Hugel(A145020) — step0: 평가대상 자기 자신 — peer 통계 자기포함은 순환논법`.
실측 재현: peer 5사 → 자기제외 → 진짜 peer 4사.

**R15 터미널 할인기간 선언** — `check_terminal_discount_convention`. 단순 WARN 은
잔소리가 되므로 **대안 컨벤션의 주당 영향을 함께 계산**해 붙인다(판단 재료).
엔진 실측 `t=9.5 → t=10 이면 주당 −2.0%` 로 문서 수기계산 −2.1% 과 독립 일치.

> ⚠️ **구현 중 자체 결함 2건 — 이번 레퍼런스의 교훈이 그대로 재현됨**
> ① `inp.n_years()` 는 **페이드 확장 전** 길이라 대안 기간이 `t=5` 로 잘못 잡혔다
> (명시 5 + 페이드 5 = 10 인데). → 확장 로직을 재구현하지 않고 **`result` 에서 역산**
> (`-ln(pv_factor[-1])/ln(1+WACC)`)하도록 수정.
> ② 그 역산이 `2.5000000000000004` 를 내어 정확일치 비교가 실패했다 — **§4 D1 과 같은
> 함정**. `round(eff, 6)` 로 정규화. 두 건 모두 회귀 테스트로 고정.

## 6.6 R3 실배선 — 교차방법 브리지 게이트 (2026-07-20)

`check_bridge_consistency` 는 함수만 있고 실제 두 방법을 이어주지 않았다. 이제
**`check_cross_method_bridge`** 가 DCF ↔ 상대가치를 직접 대조한다.

**핵심 설계 — 오탐 없는 1차 신호로 순포지션 사용**:
```
순포지션 = 순차입부채 − 비영업자산 + 비지배지분      (EV 에서 차감되는 총액)
지분가치 = EV − 순포지션
```
DCF 는 3분해, 상대가치는 `net_debt` 스칼라 1개를 쓰는 게 실무 관행이다(비영업자산을
net_debt 에 접어 넣음). 항목별로 곧장 대조하면 **"상대가치에 비영업자산 누락" 오탐이
상시 발생**하므로, 1차 판정은 항상 비교 가능한 **순포지션 스칼라**로 한다.
상대가치가 항목을 *명시 선언한 경우에만* 항목별 엄격 대조를 추가로 돌린다.

**주식수도 같은 자리에서 대조** — 브리지가 같아도 분모가 다르면 주당가치가 어긋난다(D7).
한쪽이라도 주식수가 없으면 판정하지 않는다(추측 금지).

| 실측 | DCF 순포지션 | 상대 순포지션 | 판정 |
|---|---|---|---|
| 모델러스 D3 | −426,191 (순현금) | +26,518 (순부채) | ⚠ Δ452,709 + 주식수 불일치 |
| 실무 관행(비영업자산 fold) | 70,000 | 70,000 | ✅ PASS (오탐 없음) |

**표면**: `/api/bridge/check` → 프론트 `Dashboard` 의 **"방식별 가치 비교" 카드 바로 위**에
배너로 노출. 비교 그래프를 보기 **전에** "비교해도 되는 상태인가"를 먼저 알린다.
산식은 클라이언트에서 재구현하지 않고 서버 결정론 게이트를 호출한다.
