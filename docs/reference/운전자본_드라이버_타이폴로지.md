# 운전자본(WC) 드라이버 타이폴로지

DCF의 FCFF는 `NOPAT + D&A − CAPEX − ΔNWC`. 여기서 **ΔNWC(순운전자본 증감)**가 현금흐름을
좌우한다. 매출 추정([[매출추정_논리_타이폴로지]])이 "P×Q, Q를 뭘로?"였다면, WC는 **회전기일로
환원되고, 차이는 "회전기일을 어떻게 고정하느냐"**다. 골든=[[리포트예시_클래시스]]·
[[모델러스_통합모델_5.4]](R12)·[[peer_dcf_클래시스_솔루엠]]·[[FDD_재무실사_정상화]], 실전=SMIC.

> **NWC = 매출채권 + 재고자산 − 매입채무 (− 선수금 등)**. 이익이 아니라 **현금 타이밍**의 문제.

## 핵심 공식 (실행 가능)
```
매출채권(AR)  = 매출     × DSO / 365       # Days Sales Outstanding
재고자산(Inv) = 매출원가  × DIO / 365       # Days Inventory Outstanding
매입채무(AP)  = 매출원가  × DPO / 365       # Days Payable Outstanding
NWC = AR + Inv − AP  ;  ΔNWC = NWC_t − NWC_{t-1}
```
→ [[가정원장_방법론]]의 자기정합성 검산 대상: **매출채권_보고 ≟ 매출 × DSO / 365**.

## 드라이버 아키타입

| # | 방식 | 정의 | 출처 |
|---|---|---|---|
| W1 | **회전기일 — 최근연도 고정** | DSO/DIO/DPO를 최근연도 실적으로 고정 후 유지 | 클래시스 `wc.py` 정본 |
| W2 | **회전기일 — lookback 평균 + 사유** | 과거 N년 평균, 이상치 연도는 사유 명시 제외 | 모델러스 R12 |
| W3 | **% of Sales** | NWC 각 항목을 매출 대비 비율로 단순 연동 | peer_dcf(솔루엠) |
| W4 | **기말잔액 직접 역산** | 사업 성격 반영해 기말 AR/재고/AP를 직접 추정 | SMIC(Fluence·Lonza) |
| W5 | **Target NWC(peg)·정상화** | 실사/거래 관점 — 정상 NWC 수준을 peg로 가격조정 | FDD 실사 |

### W1. 회전기일 — 최근연도 고정
가장 단순·보수적. **회전기일을 최근연도 실적으로 고정**하고 전 추정기간 유지(클래시스 정본).
매출 성장에 비례해 AR/재고/AP가 자동 확장. 함정: 최근연도가 비정상(일시적)이면 왜곡.

### W2. 회전기일 — lookback 평균 + 사유
모델러스 R12: 과거 창(window)의 회전기일 평균을 쓰되 **이상 연도는 사유를 명시하고 제외**
(provenance 규율). W1보다 견고하나 창 선택이 자의적.

### W3. % of Sales
NWC를 매출의 일정 비율로 통째 연동(솔루엠). 항목 분해 없이 빠름. 함정: 매출원가 연동 항목
(재고·매입채무)을 매출에 붙이면 마진 변동을 못 담음.

### W4. 기말잔액 직접 역산
사업 성격(수주형·계약형)이 특수하면 회전기일 대신 **기말 잔액을 직접 추정**. 실례:
- **Fluence**(ESS): "NWC = 매출채권·재고·매입채무, 사업에 따라 기말 잔액 역산."
- **Lonza·HD현대마린솔루션**: 기말 AR/Inv/AP 개별 추정 후 ΔNWC.
프로젝트/수주형(선수금·계약자산 큰 경우)에 적합.

### W5. Target NWC(peg)·정상화
거래·실사 관점([[FDD_재무실사_정상화]]): 인수 시 **정상 NWC 수준(peg)**을 정하고 실제와의
차이로 **가격조정**(pro forma). 계절성·일시 항목을 정상화. M&A SPA의 가격 메커니즘.

## 교차 관찰 (매출 타이폴로지와 대칭)
1. **거의 모든 WC = 회전기일로 환원**, 차이는 "회전기일 고정 방법"(최근연도 W1 / 평균 W2 /
   %Sales W3 / 역산 W4 / peg W5). → 플랫폼 WC 위저드 = 이 5지선다 라우터.
2. **AR/선수금은 매출 연동, 재고/매입채무는 매출원가 연동** — %Sales로 뭉뚱그리면 마진 변화를
   놓친다. 항목별 base(매출 vs 매출원가) 분리가 규율.
3. **회전기일 provenance** — 최근연도인지 평균인지 peer인지 명시해야 감사 방어(모델러스 R12).
4. **자기정합성 검산**: 리포트가 제시한 DSO로 AR을 재현하는가? 안 맞으면 [[가정원장_방법론]]의
   claimed↔applied gap(케이씨 사례와 동형).

## ⭐ 파일럿 실증 — HD현대마린솔루션 (2026-07-25): WC 자기정합성 검산 통과
가정 `매출채권 = 매출 × DSO/365`(W1 회전기일 고정)를 실행:
- 서술 = "매출채권 회전 패턴 급변 유인 작다 → 과거 추이 유지" → 함의 DSO **94.5~105.4일(중앙 ~99)**로 안정.
- `dso_applied=99`로 검산: 예측 vs 보고 매출채권 = **3/3 정합**(잔차 0.1~4.8%, 원장 `_ledger/
  HD현대마린솔루션_20261.wc.yaml`).
- → **케이씨 매출(서술 0.436% ≠ 적용 0.30%, 실패)과 반대로 WC 서술이 자기 숫자와 정합** = 통과.
  같은 원장 프레임([[가정원장_방법론]])이 매출·WC 양쪽에서 claimed↔applied를 판정.

`python scripts/assumption_check.py docs/reference/smic/_ledger/HD현대마린솔루션_20261.wc.yaml` → `✓ 3/3`.

## 활용
- 플랫폼 WC 입력 라우터(W1~W5) + 항목별 base 분리 + 회전기일 provenance 게이트.
- WC 벤치마크: 산업별 DSO/DIO/DPO 분포([[벤치마크_분포]] 확장 축).
- 가정 원장에 WC 가정 편입 → `매출채권 = 매출 × DSO/365` 자기정합성 검산.
