# 가정 원장 (Assumption Ledger) — narrative ↔ number 다리

리포트의 본질은 **"숫자를 정당화하는 산문"**. §투자포인트·§매출추정은 내러티브, appendix
추정손익·DCF는 숫자. 둘을 잇는 원자 단위는 **가정(assumption)** — 하나의 가정이 *주장·공식·값·
근거·산출숫자·원문위치·출처*를 동시에 가진다. 이 원자를 잡으면 내러티브↔숫자가 자동 연결된다.

case doc의 `revenue_drivers[].logic`(산문 문자열)를 **구조화 가정 레코드**로 승격한 것. SSOT=
`smic/_ledger/<slug>.yaml`. 검산=`scripts/assumption_check.py`.

## 스키마
```yaml
inputs:
  전방_기계장치_capex: {"2024E": 51825, "2025E": 57761}   # 십억원
assumptions:
  - id: kc_별도_capex연동
    claim: "..."                       # 내러티브 주장
    driver_type: 전방Capex연동          # 아키타입(A~K) 연결
    formula: "전방_기계장치_capex * ratio * 1000"   # 실행가능
    params: {ratio: 0.00436}           # 숫자
    basis: 과거평균(2019-2023 5yr)      # 근거 유형
    output_reported: {"2024E": [211779, 236027]}   # 리포트 표에서 관측(백만원)
    source_span: {line: 2257}          # 원문 위치
    provenance: "삼성·SK Capex 컨센서스(외부)"
    audit_flag: 전방_컨센서스_의존       # 감사 트랙
```

## 이 원장이 여는 5가지 (기존 근육 재사용)
1. **자기정합성 검산 (narrative→number)** — formula를 inputs에 실행 → output_reported와 비교.
   잔차가 tolerance 내면 "산문이 자기 숫자를 재현"을 입증. [[검증_클래시스_DCF]]·checks.py CHECK행과
   동일 정신. **잔차가 크면 방법론 차이/오류를 가리킨다**(진단 도구).
2. **span 태깅** — [[structured_meta_pipeline]](charIndex span 추출) 근육으로 숫자 셀 ↔ 근거
   문장 연결. 숫자→근거 역추적.
3. **횡단 분포 = 벤치마크 prior** — 같은 driver_type의 value를 전 리포트에서 집계 → 분포.
   플랫폼이 사용자 가정을 이 분포 대비 이상치 탐지([[매출추정_논리_타이폴로지]]와 결합).
4. **민감도 브리지** — 가정→산출→목표가 델타 사슬. 각 내러티브 주장에 "밸류의 X%" 꼬리표.
5. **프로버넌스 그래프(감사)** — `(가정, justified_by, span)`·`(가정, sourced_from, 컨센서스)`
   트리플. "출처 없는 가정"(리스크) 쿼리. [[감사인검토_WACC방법론]] provenance 규율 직결.

## ⭐ 파일럿 실증 — 케이씨 (2026-07-25): 검산이 내러티브↔숫자 불일치를 포착
가정 `케이씨(별도) 매출 = 0.436% × 전방 기계장치 Capex`를 실행:
- 2024E 예측 = 0.436% × 51,825십억 = **225,957 백만원**
- 리포트 실제 별도 매출(`parse_financial_tables.py` 추출) = **155,806 백만원** → 잔차 45%, **검산 실패**.
- **역산 함의 비율 = 0.301%(2024E)·0.285%(2025E)** ≠ 서술된 0.436% 평균. 원문에 연도별 비율
  (0.386/0.303/0.446/0.434/0.436)이 있어 **평균 단일이 아니라 연도별(하향) 적용**으로 추정.
- → 검산이 **산문(0.436%)과 표(≈0.30%)의 gap을 자동 포착** = "검토 필요" 플래그. 럽버스탬프가
  아닌 **진단 도구**. (감사·리뷰가 원하는 기능.)

> ⚠️ **방법론 교훈**: 처음 손으로 넣은 output 대역 `211,779~236,027`은 케이씨별도 매출이 아니라
> **Capex 숫자 파편**(54,2**36,027**)이었고 false pass를 냈다. **자동 표 추출(P2)이 손 입력
> 오류를 교정**하고 진짜 gap을 드러냄 — 표 파싱이 원장의 신뢰 기반인 이유.

`python scripts/assumption_check.py docs/reference/smic/_ledger/케이씨_20241.yaml` → `✗ 0/2, gap 포착`.

## 표 숫자 추출 (P2, 완료) — `scripts/parse_financial_tables.py`
get_text 선형화 표를 `[연도헤더]→[라벨]→[값런]` 규칙으로 역파싱. **연결 추정손익 top-line은
견고**(매출액 2024E=768,764 ✓, **105/182편 매출E 자동검출**). 단 **세그먼트 미니표는 컬럼정렬
위험**(연도수 상이) → 핵심행(매출액·영업이익·순이익) 우선 신뢰, 세그먼트는 vision/수기 검증.

## P1 규명 완료 — claimed vs applied 분리
원장에 `ratio_claimed`(서술 0.436%) + `ratio_applied`(실제 0.301%/0.285%, 연도별 dict) 병기.
`assumption_check.py`가 연도별 param dict를 지원 → **재검산 2/2 통과(잔차 0.1%)**. 결론: 케이씨는
서술(5yr avg 0.436%)과 달리 **2023 수준(~0.30%)을 유지한 보수적 적용** → 서술이 동인을 45% 과대
표현. **원장이 claimed↔applied gap을 감사 트랙에 노출** = "서술이 스프레드시트와 다른가"의 자동 검출.

## 확장 로드맵
- ✅ **P1** 케이씨 formula 정련(claimed vs applied 연도별 ratio) → 재검산 2/2 통과.
- ✅ **P2** appendix 표 숫자 추출(`parse_financial_tables.py`, top-line 105/182) → output_reported 자동.
- **P3** driver_type별 value 횡단 집계 → 벤치마크 분포(플랫폼 assumption 게이트).
- **P4** 감사 audit_flag·finding 집계 → 내러티브↔숫자 gap·provenance 없는 가정 리스트(감사 트랙).
