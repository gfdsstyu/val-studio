# 파서 아키텍처 — 불러오기 방식 × 자료유형 매트릭스

> 파서는 **두 축의 곱**으로 설계한다:
> - **불러오기 방식(input method)** = 바이트→데이터 추출 *엔진* (엑셀·PDF·XBRL·DART API)
> - **자료유형(document type)** = 데이터의 *의미·고정구조* 프로파일 (사업보고서·IR·리서치·의견서)
>
> 둘은 **직교**한다: 한 자료유형이 여러 방식으로 오고(사업보고서 = XBRL or PDF), 한 방식이
> 여러 유형을 담는다(PDF = 의견서·리서치·IR). **추출 백엔드(방식)** 위에 **시맨틱 프로파일(유형)**
> 을 얹는 2층 구조.

---

## 0. 제1규칙 (실측) — 같은 자료도 방식따라 품질 극단적

삼성전자 사업보고서를 XBRL·PDF 두 방식으로 실측:
| 방식 | 한글 | 구조 | 결과 |
|---|---|---|---|
| **XBRL** | ✅ 온전(lab-ko) | ✅ 태그·차원 | 영업수익 79조 정확, 410 연결 fact |
| **PDF** | ❌ **CID 깨짐**(목차 제목 공백) | 표 공간배치만 | 숫자만 생존, 574p 중 고신뢰 0 |

→ **DART 정형공시(사업보고서·재무제표)는 XBRL 우선. PDF는 OCR 폴백.**
외부평가의견서·리서치는 XBRL 부재 → PDF(+OCR) 유일.

## 1. 불러오기 방식(Axis 1) — 추출 백엔드

| 방식 | 모듈 | 상태 | 산출 | 강점 / 함정 |
|---|---|---|---|---|
| **DART API** | `dart_client.py` | ✅ | 파싱된 계정(JSON) | 편리·요약. 주재무제표만. `fnlttSinglAcntAll` |
| **XBRL(원문)** | `parsers/xbrl.py` | ✅ | fact⋈context(계정·기간·차원) | **최상위 신뢰**(OCR·CID무관), 세그먼트·연결/별도. 차원필터 필요 |
| **PDF** | `parsers/pdf.py` | ✅ | 표 셀격자 + RAG 청크 | 표=우측정렬 클러스터링. **DART PDF 한글 CID깨짐→OCR** |
| **엑셀** | `parsers/xlsx.py` | ⛔ 미구현 | 셀·수식값 | 모델·리포트 예시. openpyxl(복호화 msoffcrypto) |

공통 백본: `parsers/base.py`(emit→정규화·검증·출처) + `provenance.py`(출처추적) +
`validators.py`(4종 tie-out). 모든 방식이 `ProvenancedValue`로 수렴.

### OCR 경로 (PDF 한글 CID 대응)
`pdf.py`의 `garble_ratio`가 한글 손실 감지 → `confidence<0.6`이면 OCR 라우팅(method=OCR).
OCR 백엔드(예정 `parsers/ocr.py`): 한국어 tesseract / Google Document AI / Upstage.
CID 폰트는 ToUnicode CMap 부재라 어떤 텍스트추출기도 불가 → **OCR만이 해법**.

## 2. 자료유형(Axis 2) — 시맨틱 프로파일

| 유형 | 주 방식 | 소비 | 고정구조 / 시맨틱 |
|---|---|---|---|
| **사업보고서** | **XBRL**(우선), PDF(OCR) | 엔진·감사·RAG | IFRS 계정 태그·주석·세그먼트. 고정 목차 |
| **외부평가의견서** | PDF(+OCR) | 감사인 트랙·RAG·의견서생성 | ⭐고정양식(§[[외부평가의견서_고정양식_구조]]): WACC/영구성장/SOTP 앵커 |
| **증권사 리서치** | PDF | RAG 지식원천 | 목표주가·컨센서스·산업 CAGR([[참고보고서_활용]]). 서사형 |
| **IR 자료** | PDF(PPT) | RAG 컨텍스트 | 사업·세그먼트·가이던스. 서사+표 혼합 |

각 유형 = 시맨틱 프로파일(예정 `profiles/`):
- **structured 대상**(사업보고서·의견서 표): 표→계정 매핑 + tie-out + 엔진투입.
- **narrative 대상**(리서치·IR): RAG 청크(text_chunks) + 출처.
- **고정양식 대상**(의견서): 섹션 앵커 기반 결정론 추출(`opinion_template.py` 예정).

| 유형 ＼ 방식 | XBRL | PDF | DART API | 엑셀 |

| **증권사 리서치** | — | ✅ RAG청크 | — | — |
| **IR 자료** | — | ✅ RAG청크 | — | 가끔 |
| **평가모델/리포트** | — | — | — | ✅ xlsx |

셀 = (추출 백엔드) + (시맨틱 프로파일). 예: (의견서×PDF) = `pdf.py` 표추출 +
`opinion_template.py` 앵커 + OCR(한글) + `sotp` 조립.

## 4. 구현 현황 & 로드맵
- ✅ 백본(base·provenance·validators), DART API, XBRL, PDF(표+RAG), 주석추출.
- ⛔ **엑셀 파서**(`xlsx.py`) — 모델·리포트 예시·복호화(msoffcrypto).
- ⛔ **OCR**(`ocr.py`) — DART PDF 한글·스캔 의견서. 최우선(한글 데이터 잠금해제).
- ⛔ **시맨틱 프로파일**(`profiles/` or `opinion_template.py`) — 유형별 고정구조 앵커·필드맵.
- ⛔ **라우터**: (방식 감지 + 유형 감지) → 적정 파서·프로파일 자동 선택.

> 설계 원칙: **방식(추출)과 유형(의미)을 분리**해야 조합폭발 없이 확장된다. 새 방식 추가 =
> 백엔드 1개, 새 유형 추가 = 프로파일 1개. N×M 이 아니라 N+M.
